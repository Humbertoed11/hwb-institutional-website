Standard Operating Procedure: Website Architectural Flowchart SOP

1.0 Purpose

To define the visual and logical structure of the HWB Cleaning Services LLC web platform. This SOP provides a technical roadmap of how the public website, self-service onboarding portals, backoffice command center, and controlled QMS manual interact with PostgreSQL 16.15 and autonomous AI agents.

2.0 Scope

Applies to the Cloudflare Anycast Edge ("Pincer Shield"), the Microsoft Azure Web App for Containers (`:5000`, 24-channel Gunicorn workers), the unified Flask application (`main_app.py`), and PostgreSQL 16.15 (`sigmajan-server` / `hwb_postgres_dev`).

3.0 Universal Mandates (2026 Baseline)

  1. Physical Truth: All flowchart nodes must represent real production routes, blueprints, and database tables.
  2. Logic Proof: Every path in this diagram must be verifiable locally at 127.0.0.1:5000 and in production at https://www.hwbcleaning.com.

4.0 Procedure

4.1 System Topology

The HWB infrastructure operates across four unified tiers: 1. Edge Perimeter Tier: Cloudflare Anycast SSL/TLS 1.3 and 15-CIDR Azure Origin Shield. 2. Web & Backoffice Application Tier: Unified Gunicorn (3 workers × 8 threads = 24 concurrent slots) running `main_app.py` (`public_bp`, `crm_api_bp`, `auth_bp`). 3. Controlled QMS Gatekeeper Tier: Role-partitioned `/manual` reader serving canonical `static/qms/*.html` procedures. 4. Database & Encrypted Vault Tier: PostgreSQL 16.15 (`84` public tables, `pgvector 0.8.2`, AES-256 `BYTEA` document vaults, and WORM `SecurityAuditLogs` triggers).
