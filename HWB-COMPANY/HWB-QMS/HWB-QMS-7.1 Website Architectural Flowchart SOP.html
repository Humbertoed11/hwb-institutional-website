Standard Operating Procedure: Website Architectural Flowchart SOP

1.0 Purpose

To define the visual and logical structure of the HWB Cleaning Services ecosystem. This SOP provides a technical roadmap of how the website interacts with the database, agents, and compliance engine.

2.0 Scope

Applies to the Main Web App (Flask), the Compliance Engine (Nginx), and the Traffic Director (Gateway).

3.0 Universal Mandates (2026 Baseline)

1. Physical Truth: All flowchart nodes must represent real server paths.

2. Logic Proof: Every path in this diagram must be verifiable at mop.test:5000 or mop.test:8000.

4.0 System Topology

The HWB infrastructure is decoupled into three primary segments:

  1. Public/CRM Segment: Handles sales, lead ingestion, and marketing routes (including the prefix-free templates and the newly added methodology route).
  2. Compliance Segment: Dedicated Nginx container for document control, serving QMS documents in HTML format.
  3. Database Segment: PostgreSQL persistence for all transactional records, including system recovery tables.

5.0 The Architectural Flowchart

graph TD A[Visitor/Staff] -->|Port 8000| B[Traffic Director Gateway] B -->|/manual| C[Compliance Engine Nginx] B -->|/admin or /crm| D[Web App Engine Flask] B -->|Marketing Pages: /, /about, /ehsq, /methodology, /services/*, /get-quote| D D -->|SQL| E[PostgreSQL DB] D -->|Logic| F[AI Agent George /core] C -->|Fragments| G[Static HTML SOPs] D -->|Signal| H[Teams/Email Alert]

6.0 Verification (Zero-Defect Check)

  • The flowchart renders correctly in the HTML manual index.
  • The "Traffic Director" correctly routes /manual to the Nginx host.
  • Database calls are being logged to Tier 6.
  • All public marketing routes render prefix-free templates successfully.

7.0 Notes and Cautions

LOGIC

Using a separate Compliance Engine prevents OOM crashes on the main app.

CAUTION

Do not change Gateway routing without a Peter Sentinel snapshot.
