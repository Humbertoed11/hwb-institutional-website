Standard Operating Procedure: Backend Architecture and Enterprise Standards

1.0 Purpose

This procedure establishes the 100% Enterprise Hardening Standard across all software systems at HWB Cleaning Services LLC. The purpose is to eliminate monolith code, temporary workarounds, and unmanaged database connections. Every engineering change must operate to Fortune 500 standards, protecting company records and guaranteeing continuous system uptime.

2.0 Scope

This standard applies to all software engineers, autonomous AI agents, technical contractors, and administrative systems operating within the HWB ecosystem, including the web application, background workers, databases, and APIs.

3.0 The Zero-Hotfix Enterprise Mandate

The Institutional Law

Only enterprise-level solutions are permitted in the HWB codebase. Ad-hoc hotfixes, local workaround scripts, and quick patches are strictly prohibited.

When an issue or security gap is discovered, developers must find the root cause in the architecture and fix the system as a whole, rather than patching a single screen or endpoint.

4.0 The 8 Pillars of Enterprise Architecture

Pillar Core Requirement Industrial Purpose
1. Modular Domain Blueprints Deconstruct monoliths into small domain blueprints. The application core must remain under 400 lines. Eliminates code collisions and enables safe multi-developer collaboration.
2. Threaded Connection Pooling All database queries must reuse warm connections from a managed pool (ThreadedConnectionPool). Reduces database latency from 18ms to ~1ms and prevents socket exhaustion during traffic spikes.
3. Abuse Defense & Rate Limiting Public forms and authentication routes must enforce sliding-window IP rate limits. Blocks brute-force password guessing and automated web quote spam.
4. Inbound Data Sanitization All inputs (phone, email, currency, sqft, zip) must pass through a standard cleaning gateway before saving. Guarantees 100% data consistency across CRM records and background scrapers.
5. Managed Background Task Queue Long-running jobs must execute through a thread pool with auto-retries and execution telemetry. Prevents worker timeouts and ensures failed background tasks are retried cleanly.
6. Declarative Role Security Enforce explicit decorators like @roles_required and centralized request quarantines. Ensures permissions are self-documenting and impossible to bypass.
7. Version-Controlled Migrations All database table alterations must run through an idempotent schema migration engine. Eliminates raw DDL on server boot and preserves database schema integrity.
8. Automated CI/CD Quality Gate Every commit must pass 100% of the master automated test battery (54 tests) before release. Proves zero regressions exist before deploying code to live customers.

5.0 Modular Blueprint Architecture

The main application core (main_app.py) functions strictly as a Twelve-Factor application factory, configuration hub, and security gatekeeper (337 lines). All domain logic is divided into 6 modular Blueprints:

  • Telemetry Blueprint (blueprints/telemetry.py): System health, database connection pool metrics, container ping, and live task queue telemetry.
  • Commercial Bids Blueprint (blueprints/bids.py): Subcontractor prequalification, CSI MasterFormat map, TMA estimator, and construction bid tracking.
  • Authentication Blueprint (blueprints/auth.py): Login, logout, heartbeat, and session security protected by rate limiting.
  • Public Marketing Blueprint (blueprints/public.py): Homepage, service brochures, location guides, digital QMS manuals, robots.txt, sitemaps, and quote intake.
  • Operations Blueprint (blueprints/operations.py): Management hub, Field Sales Desk, lead/account editor, scope builder, chemical master repository, and executive controls.
  • CRM REST API Blueprint (blueprints/crm_api.py): Structured endpoints for leads, accounts, touchpoints, AI knowledge scar search, and duplicate resolution.

6.0 Database Connection Pooling & Latency Optimization

To eliminate TCP handshake delays, all PostgreSQL connections are managed by a ThreadedConnectionPool (minimum 2, maximum 20 connections) in core/services/database.py. A transparent proxy (PooledConnection) returns sockets to the pool upon calling conn.close(), cutting query turnaround time from 18.38 ms to 1.26 ms.

7.0 Abuse Defense & Rate Limiting

A thread-safe sliding-window rate limiter (core/services/rate_limiter.py) governs incoming requests by client IP address:

  • Login Gate: Limited to 10 attempts per minute per IP to thwart brute-force attacks.
  • Quote Form Gate: Limited to 15 submissions per minute per IP to block bot flooding.
  • Violation Handling: Exceeding quota returns an HTTP 429 Too Many Requests response with a standard Retry-After header.

8.0 Managed Background Task Queue

Background jobs (such as GC planroom bid sync and scraper daemons) are managed by core/services/task_queue.py. The queue runs up to 4 worker threads concurrently, provides live status reporting at /api/v1/tasks, and automatically retries failed tasks up to 2 times using linear backoff.

9.0 Inbound Data Sanitization Gateway

All user and scraper data must pass through core/services/sanitizer.py before database insertion:

  • Phone Numbers: Formatted strictly to (###)-###-####; 11-digit leading '1' stripped; garbage entries rejected.
  • Currency: Cleaned to standard numeric float values.
  • Square Footage: Non-numeric characters stripped and cast to clean float values.
  • Zip Codes: Standardized to 5-digit postal format.
  • Email: Lowercased, whitespace stripped, and validated for valid email syntax.

10.0 Automated CI/CD Testing & Zero-Regression Battery

All developers and automated agents must execute python scripts/run_all_tests.py before committing code. This master battery tests 54 automated verification points across 7 test suites, achieving a 100% pass rate in approximately 6 seconds.
