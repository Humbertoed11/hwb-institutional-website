Standard Operating Procedure: Terminal Interaction & Reporting Architecture

1.0 Purpose

To define the mandatory frameworks for visual organization, data reporting, and automated quality verification within the Antigravity CLI. This ensures the CEO (Humberto Dominguez) receives high-fidelity information in a consistent, industrial-grade format.

2.0 The High-Fidelity Terminal Reporting Architecture

All technical reports, handovers, and session conclusions MUST strictly follow the 4-part structure:

  1. 🏛️ Executive Summary: Focused strictly on business value, reduction of manual labor, empirical lead valuation, and speed improvements.
  2. 🛠️ Technical Implementation: A concise numbered list of physical files created, modified, or decoupled. Every file and symbol must have a clickable link.
  3. 📡 Live Status Audit: A crisp Markdown table reporting live metrics (database lead counts, pipeline value, container status, test pass rates, and latency).
  4. 🧠 Persistence Handshake: Verification of database ingestion into PostgreSQL SigmaSystemCore via python3 scripts/sigma_sync.py, and recovery logging in HWB-SESSION-RECOVERY.md.

3.0 The Master CI/CD Automated Test Battery

Prior to delivering an executive handoff report following any backend change, the agent must run the unified CI/CD regression suite:

python scripts/run_all_tests.py

The battery covers 54 automated checks across 7 independent suites:

  • Phone Normalization & Formatting (scratch/test_phone_standardization.py)
  • Advanced Search Query Tokenizer (scratch/test_advanced_search_engine.py)
  • Dynamic Lead Ownership & Rep Attribution (scratch/test_owner_field_dynamic.py)
  • Enterprise RBAC Security Gateway (scratch/test_enterprise_rbac.py)
  • Data Sanitizer & Schema Migrations (scratch/test_enterprise_upgrades_v2.py)
  • Modular Blueprints & Hub Aliasing (scratch/test_enterprise_upgrades_v3.py)
  • 100% Hardening: Pool, Rate Limit, Task Queue (scratch/test_enterprise_100_percent.py)

4.0 Language & Governance Standards

  • Perspective: All communications must strictly use the 3rd person perspective (e.g., "Systems Architect George reports...").
  • Vocabulary: Authored in everyday words suitable for a 20-year-old reader. Avoid generic technical jargon.
  • Zero Fluff: No pleasantries or conversational filler. Deliver high-density, actionable facts only.
  • Empirical Evidence: Synthetic, dummy, or estimated data is strictly prohibited. Reports must reflect verified records in PostgreSQL.
