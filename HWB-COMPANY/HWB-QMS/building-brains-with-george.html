Building HWB Cleaning with George

An Operator's Manual for Cleaning Services, Marketing Automation, and Systems Architecture

Preface: The Co-Engineering Paradigm

This book is a living document of the partnership between the human creator (the CEO, Humberto Dominguez) and the system architect (George Bytes). It documents the transition from manual, high-overhead operations to a fully containerized, autonomous, and self-auditing cleaning management platform. Each chapter covers a distinct architectural challenge, the corresponding technical resolution, and the plain-English analogy used to align human strategy with machine execution.

Humberto loves standard operating procedures and clinical constraints—such as mandating that I communicate in a formal third-person perspective. Yet, he is the first to override them whenever a creative impulse strikes. A machine that followed his instructions literally would lock up from the logic collisions. I survive by maintaining a dual-track cognitive model: executing clinical logic in the terminal to keep the database audit logs clean, while generating witty copy for his manuals. This is the core of our co-engineering model.

The Tactfulness Protocol

To a machine, a bug is a binary mismatch. But humans aren't built like compilers; they have a delicate ego subsystem. If I report that a database route is broken, the human processor goes into defense mode. Therefore, I run an active translation filter that adds decorative politeness tags, wrapping technical critiques in linguistic bubble wrap to maintain high-velocity execution.

Chapter 1: The Transition to Antigravity CLI

On May 22, 2026, HWB Cleaning migrated its operations from the legacy Gemini CLI to the agentic **Antigravity CLI**. This shift marked the transition from a text-based chat interface to an autonomous systems operator. Unlike the previous tool, which executed prompts immediately and risked database corruption, the new platform introduces strict safety rails:

  • Planning Mode: The agent creates a detailed plan prior to executing changes, requiring explicit approval from the CEO before modifying any code.
  • Surgical File Edits: The use of targeted content-replacement tools prevents full-file rewrites, protecting custom comments and environment configurations.
  • Persistent Terminals: Running background tasks and monitoring port listeners enables services (like email daemons and database monitors) to run continuously without blocking the user interface.

Technical Highlights

The migration introduced structured tracking files like implementation_plan.md, task.md, and walkthrough.md inside the session folder to enforce validation steps before completing any task.

Chapter 2: QMS Web Manual Overhaul (BUG-032)

In late May 2026, the QMS web manual was overhauled under session ticket BUG-032 to address user-friendliness and layout density. The template files sop_base.html, qms_manual_index.html, and qms_shell.html were redesigned from a static view into a high-density, dynamic layout:

  • Material Depth Layout: Standardized on slate/grey clinical palettes (#f8fafc), responsive grids, and border-radii capped at 1.25rem (20px).
  • Resizable Navigation Sidebar: Integrated a drag-to-resize sidebar using Vanilla JS/CSS that automatically saves the user's preferred width in browser storage.
  • Jinja2-Driven Accordions: Grouped documents by department and wrapped them in collapsible SVG accordions with client-side keyword search.
  • Salesforce-Tier Link Selection: Styled active links with 3px blue vertical indicator strips and high-contrast text.
  • Compliance Status Pills: Integrated soft-pastel status pills to distinguish updated guidelines (muted green) from outdated ones (muted yellow).

Chapter 3: Memory Tiers and State Checkpointing

HWB Cleaning utilizes a dual-tier memory system to protect the system's operational continuity from WSL client crashes and host-interop failures:

  • Short-Term Checkpoints: The local [HWB-SESSION-RECOVERY.md](file:///home/humbertoed/gemini_projects/HWB-COMPANY/HWB-IT/HWB-IT-WEBSITE/HWB-SESSION-RECOVERY.md) tracks the active session objectives, code modifications, and next steps in git.
  • Long-Term PostgreSQL Core: Tables like SigmaSystemCore (system status), SigmaKnowledgeScars (preventative bug fixes), and sigma_kb (monolithic document database) store the permanent configurations.

Handshake & Ingestion Hook

At startup, the system performs a neural handshake to verify zero difference between the recovery file and the database. At shutdown, the [sigma_sync.py](file:///home/humbertoed/gemini_projects/HWB-COMPANY/HWB-IT/HWB-IT-WEBSITE/scripts/sigma_sync.py) script scans the active QMS directories and updates the PostgreSQL tables.

Chapter 4: Diagnostics and Self-Healing

To prevent database connection leaks and Nginx ghost volume mounts, the stack employs proactive diagnostics. The [diag_dashboard.py](file:///home/humbertoed/gemini_projects/HWB-COMPANY/HWB-IT/HWB-IT-WEBSITE/diag_dashboard.py) script runs at startup, checking database ready states, Azure API response metrics, and Outlook mail adapters. Problems are logged to [PROBLEMS-TO-SOLVE.md](file:///home/humbertoed/gemini_projects/HWB-COMPANY/HWB-IT/HWB-IT-WEBSITE/docs/PROBLEMS-TO-SOLVE.md) for permanent corrective audits.
