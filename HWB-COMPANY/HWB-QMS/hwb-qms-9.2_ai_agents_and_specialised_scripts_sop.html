Standard Operating Procedure: AI Agents & Specialized Automation Scripts

1.0 Purpose

This standard operating procedure defines the execution standards, process supervision rules, and operational boundaries for all autonomous AI agents and specialized background scripts operating within the SigmaFidelity™ infrastructure. The goal is to eliminate manual administration, enforce zero-defect data processing, and maintain continuous platform availability.

2.0 Scope

This procedure applies to all background processes, supervisor daemons, cron tasks, and CLI automation utilities executed inside the hwb_agent_worker container, the web application container, and the Linux host environment.

4.0 Daemon Supervision & The Zero-Crash Mandate

  1. Worker Supervision: All background agent daemons running inside hwb_agent_worker must be registered in the AGENTS array of worker_launcher.py.
  2. Idempotency: Every script must be completely idempotent. A restart or redundant execution cycle must never duplicate database records, corrupt ongoing transactions, or clobber reconciled financial data.
  3. Strict Output Staging: Automated outreach scripts are strictly prohibited from dispatching live communications directly to prospective clients. All outbound proposals must be staged into PendingOutbox using the HWB-COM-001 official letterhead for CEO review and approval.
  4. Error Logging: If any background script encounters an unhandled exception or operational failure, the event must be immediately recorded to docs/PROBLEMS-TO-SOLVE.md per our institutional error logging mandate.

5.0 Verification (Zero-Defect Check)

  • Run docker top hwb_agent_worker to verify all 5 supervisor processes are actively executing.
  • Inspect HWB-IT-SYSTEM-LOGS/tessa_regression_audit.log to confirm the latest regression audit passed with Grade A+ certification.
  • Verify that Peter's host sentinel is running on the host via ps aux | grep peter_sentinel.
