Standard Operating Procedure: Backoffice & CRM Management Suite

1.0 Purpose

This document explains how to operate and manage the HWB backoffice and commercial customer database. It ensures that facility information remains accurate, phone numbers are formatted uniformly, field sales assignments are tracked dynamically, and unauthorized data exfiltration is prevented.

2.0 Scope

This procedure applies to all office employees, outside sales representatives, support staff, and automated systems that interact with the customer relationship management (CRM) database.

3.0 Operational Procedures

3.1 System Access and Login

To access the administrative tools:

  1. Open the web browser and navigate to the /login route.
  2. Enter your corporate username and password.
  3. The login gate enforces a sliding-window rate limit of 10 attempts per minute to stop automated brute-force attacks.
  4. Upon successful authentication, users are routed according to their role (Sales reps land directly in /admin/operations?view=leads).

3.2 Login Timeout and Inactivity Policy

To prevent unauthorized access to sensitive company and client data, an inactivity policy is enforced:

  • Inactivity Window: If no activity is detected for 30 minutes, an alert overlay appears on the screen with a 60-second countdown timer.
  • Keep Working: Clicking this button resets the timer and sends a heartbeat ping (/heartbeat) to refresh your session.
  • Backend Enforcement: The server enforces a hard 31-minute session lifetime. Requests after 31 minutes of inactivity are rejected.

3.3 Standardized Phone Formatting: (###)-###-####

All phone numbers across the entire ecosystem must strictly conform to the (###)-###-#### standard:

  • Database Storage: All phone records in Leads, Customers, Contacts, and ConstructionBids are normalized to (###)-###-####.
  • Inbound Sanitization: Any incoming phone number from web forms, manual creation, or background scraping daemons is cleaned automatically via core/services/sanitizer.py.
  • Live Keystroke Masks: All modal input fields apply a live JavaScript format mask as the user types, stripping leading '1' and formatting digits into (###)-###-####.
  • Server-Side Filter: Templates format phone values with Jinja filter | format_phone to guarantee zero unformatted records on screen.

3.4 Dynamic Sales Representative Ownership Allocation

Lead and customer account ownership is tied directly to live user accounts in the PostgreSQL Users table:

  • Hardcoded mock names have been completely eliminated. Dropdown selectors in all modals query active database users dynamically.
  • Sales representatives creating new leads or onboarding accounts automatically have the record attributed to their user account.
  • Executives can reassign single leads or bulk-assign hundreds of leads to any active sales rep using the batch actions bar.

3.5 Advanced Search Engine & Query Tokenizer

The operations grid uses an industrial search tokenizer (core/services/search.py) supporting targeted query syntax:

  • Field Targeting: city:Plano, industry:Medical, status:New, rep:Wiley.
  • Numeric Comparisons & Ranges: sqf:>=10000, sqf:<20000, value:>50000.
  • Negative Exclusions: -Church, -"School District".
  • Exact Phrases: "North Texas".
  • Wildcards: Pla*.
  • American Dates: 04/10/2026 automatically converts to SQL dates.
  • Phone Search: Accepts raw digits (2145550198) or formatted text ((214)-555-0198) utilizing functional regex database indexes.

3.6 Option B Streamlined Navigation & Data Protection

Outside Sales representatives are granted focused access to accelerate selling while protecting intellectual property:

  • Scoped Views: Sales reps access Leads, Accounts, and the Field Sales Desk. High-risk administrative tabs (GC Bids, Work Monitor, Executive) are hidden from their navigation.
  • Data Exfiltration Lockout: Bulk CSV Export buttons are hidden, and API attempts to call /api/v1/leads/export-selected or /api/v1/accounts/export-selected return HTTP 403 Forbidden.
  • Deletion Lockout: Record deletion endpoints return HTTP 403 Forbidden for Sales accounts.
  • Audit Logging: Any unauthorized navigation attempt is automatically logged as a security event in GlobalActivities.
