1.0 Objective

To provide a fast, plain-language emergency response checklist ("The Panic Button") for recovering HWB Cleaning Services LLC databases, containers, WSL2 Linux workspaces, or an entire lost workstation without risking cross-OS filesystem freezes.

2.0 Roles and Responsibilities

  • Humberto Dominguez (CEO): Final approval authority for full-system rollbacks and bare-metal nuclear restores.
  • Peter (Recovery Specialist): Autonomous owner of hourly native ext4 binary snapshots and pre-change checkpoint vaults.
  • George (Systems Architect): Technical verification lead for database integrity, container health, and post-restore audit gates.

3.0 The 3-Layer Sovereign Backup Stack (v3.1.0)

Legacy sigma-peter.service (15-minute daemon) and /mnt/c/.../OneDrive cross-OS 9P backups are permanently retired (BUG-173 / SO-SCAR-023) because 9P file locks stall WSL2. Active protection runs across three isolated layers:

  1. Layer 1 — Hardened Hourly Native ext4 Snapshots & Peter Sentinel (v2.0.0): scripts/hwb_hourly_backup.sh executes via Linux cron at :00 every hour, writing 24-hour rolling pg_dump -Fc PostgreSQL 16.15 binary dumps locked to chmod 600 with SHA-256 checksums (hwb_dev_db.dump.sha256) into backups/hourly/ and backups/latest/. Before risky edits or migrations inside /home/humbertoed/gemini_projects, python3 scripts/peter_sentinel.py checkpoint --label <name> pins a chmod 600 PG16 dump, .env copy, and complete active code/QMS archive in backups/checkpoints/<name>/ with SHA256SUMS.txt (protected from 24-hour auto-purge) and test-restores into temporary database hwb_peter_verify_tmp.
  2. Layer 2 — Tier 1 Out-of-Band Windows Rescue Cockpit (PC Intact, WSL2 Hung): Standalone Windows Antigravity workspace at C:\wsl-backup\SuperGeorge-Rescue (Request Review / ASK mode, zero L:\ Linux drive mount) paired with C:\wsl-backup\restore-system.ps1.
  3. Layer 3 — Tier 2 Grab-and-Go USB Nuclear Drive (D:\): Offline bare-metal recovery drive containing D:\Installers\, D:\restore-system.bat, D:\2026-data-backup-ubuntu\ubuntu-full.tar, and D:\SuperGeorge-Rescue.

4.0 Protocol: The "Panic Button" Sequence

STEP 1: Assess Failure Scope

  1. If Linux is responsive, inspect the session Black Box at /home/humbertoed/gemini_projects/HWB-SESSION-RECOVERY.md and run python3 scripts/peter_sentinel.py verify to confirm backup freshness (<90 minutes), chmod 600 permissions, and SHA-256 integrity.
  2. Select the exact recovery tier below matching the failure mode.

STEP 2: Execute Matching Recovery Tier

  • Scenario A — Database Drift, Row Corruption, or Full Local Rollback (Linux Healthy): Execute Peter's full staging-swap rollback from a pinned checkpoint in backups/checkpoints/<name>/ (restores into clean staging database hwb_restore_stage first, stops hwb_web_app and hwb_agent_worker briefly, swaps hwb_dev_db cleanly without open-socket or "SecurityAuditLogs" WORM trigger errors, restarts containers, and verifies all 4 worker daemons via docker top):
    python3 scripts/peter_sentinel.py rollback --label <name> --full
  • Scenario B — Uncommitted Working-Tree / Code Breakage Only (Linux Healthy): Restore active code and QMS files from the pinned checkpoint and restart hwb_web_app via python3 scripts/peter_sentinel.py rollback --label <name> --code-only (or clean working tree via git reset --hard HEAD && git clean -fd && docker restart hwb_web_app).
  • Scenario C — Tier 1 Rescue (PC Intact, WSL2 / Ubuntu Hung or Broken): Do NOT open any L:\ or WSL path. Open Windows Antigravity on C:\wsl-backup\SuperGeorge-Rescue (Request Review / ASK mode) or run C:\wsl-backup\restore-system.ps1 in Administrator PowerShell.
  • Scenario D — Tier 2 Bare-Metal / Lost PC Nuclear Restore (D:\ USB Drive):
    1. Run wsl --install -d Ubuntu in Administrator PowerShell and reboot.
    2. Install offline installers from D:\Installers\: Docker Desktop Installer.exe (Docker Hub User: hdominguez11, Email: hdominguez@hwbcleaning.com; enable Settings -> Resources -> WSL Integration -> Ubuntu after Step 3) and Antigravity-x64.exe (Google login: humbertoed@gmail.com).
    3. Double-click D:\restore-system.bat to restore the Ubuntu WSL2 image from D:\2026-data-backup-ubuntu\ubuntu-full.tar, apply .wslconfig (12GB RAM / 6 CPUs), and verify /home/humbertoed/gemini_projects and external sibling workspaces.
    4. Open Windows Antigravity -> File -> Open Folder -> D:\SuperGeorge-Rescue (or connect to WSL Ubuntu once restored) and boot the HWB container stack (127.0.0.1:5000).

STEP 3: Post-Recovery Verification

  1. Verify backup freshness, chmod 600 permissions, and SHA-256 checksum: python3 scripts/peter_sentinel.py verify.
  2. Verify HTTP health and 4 worker processes: curl -fsS http://127.0.0.1:5000/heartbeat and docker top hwb_agent_worker.
  3. Run regression and SOC 2 gates: docker exec hwb_web_app python3 scripts/test_web_performance_rack_14.py and docker exec hwb_web_app python3 scripts/check_soc2_data_leakage.py.
