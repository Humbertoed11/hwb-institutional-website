Standard Operating Procedure: Enterprise Web Performance, Twelve-Factor Stateless Workers & Edge Caching Standard

1.0 Purpose

This Standard Operating Procedure (SOP) establishes the mandatory 5-Pillar Enterprise Web Performance Standard for the HWB Cleaning Services LLC institutional web application (https://www.hwbcleaning.com/). It eliminates cold-start stalls, Gunicorn worker recycle freezes, redundant database network round-trips, per-request disk reads, oversized static image payloads, and CDN cache bypasses.

2.0 The 5-Pillar Enterprise Web Performance Standard

  • Pillar 1 — Azure App Service Infrastructure: Enforce AlwaysOn=true, Use32BitWorkerProcess=false, and HealthCheckPath="/heartbeat" on hwb-institutional-website.
  • Pillar 2 — Twelve-Factor Stateless Web Workers: Launch Gunicorn with --preload --workers 2 --threads 8 and guard startup migrations/seeders/daemons with an atomic non-blocking file lock (/tmp/hwb_enterprise_boot.lock) so worker recycles take 0ms.
  • Pillar 3 — Zero-Round-Trip Pooled Database Connections: Configure ThreadedConnectionPool with options="-c timezone=America/Chicago" and TCP keepalives at socket creation, removing per-checkout SET TIME ZONE queries and right-sizing DB_POOL_MAX=10.
  • Pillar 4 — In-Memory Version & Telemetry Cache: Decorate get_version_info() with @functools.lru_cache(maxsize=1) to eliminate per-request disk reads of /app/version.json.
  • Pillar 5 — Next-Gen WebP Image Pipeline & Split Cloudflare Edge Caching: Serve compressed .webp visuals (91% homepage size reduction) and emit Cache-Control: public, max-age=300, s-maxage=3600, stale-while-revalidate=86400 with Vary: Accept-Encoding (stripping Cookie) on anonymous public marketing GET routes.
