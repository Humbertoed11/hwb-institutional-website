Standard Operating Procedure: Enterprise Web Performance, Twelve-Factor Stateless Workers, Edge Caching, CQRS Backoffice & Universal Phone/Tablet Adaptive Table Standard

1.0 Purpose

This Standard Operating Procedure (SOP) establishes the mandatory Three-Part Enterprise Web, Backoffice & Universal Responsive Standard for the HWB Cleaning Services LLC institutional web application (https://www.hwbcleaning.com/). It eliminates cold-start stalls, Gunicorn worker recycle freezes, redundant database network round-trips, per-request disk reads, oversized static image payloads, CDN cache bypasses, synchronous backoffice HTTP/SQL stalls, and mobile/tablet layout overflow across all 28 HTML tables.

2.0 Part I: The 5-Pillar Public Surface & Stateless Worker Standard (v1.0.0)

  • Pillar 1 — Azure App Service Infrastructure: Enforce AlwaysOn=true, Use32BitWorkerProcess=false, and HealthCheckPath="/heartbeat" on hwb-institutional-website.
  • Pillar 2 — Twelve-Factor Stateless Web Workers: Launch Gunicorn with --preload --workers 2 --threads 8 and guard startup migrations/seeders/daemons with an atomic non-blocking file lock (/tmp/hwb_enterprise_boot.lock) so worker recycles take 0ms.
  • Pillar 3 — Zero-Round-Trip Pooled Database Connections: Configure ThreadedConnectionPool with options="-c timezone=America/Chicago" and TCP keepalives at socket creation, removing per-checkout SET TIME ZONE queries and right-sizing DB_POOL_MAX=10.
  • Pillar 4 — In-Memory Version & Telemetry Cache: Decorate get_version_info() with @functools.lru_cache(maxsize=1) to eliminate per-request disk reads of /app/version.json.
  • Pillar 5 — Next-Gen WebP Image Pipeline & Split Cloudflare Edge Caching: Serve compressed .webp visuals (92.7% homepage size reduction) and emit Cache-Control: public, max-age=300, s-maxage=3600, stale-while-revalidate=86400 with Vary: Accept-Encoding (stripping Cookie) on anonymous public marketing GET routes.

3.0 Part II: The 5-Pillar Post-Login CQRS Backoffice Standard (v1.1.0)

  • Pillar 1 — Async Background Telemetry Cache: 300s TTL thread-safe cache (_TELEMETRY_CACHE) in core/services/self_healing_engine.py and core/services/credential_sentinel.py; it_telemetry runs only on it_department / it_telemetry views.
  • Pillar 2 — Set-Based SQL Aggregation & Covering Indexes: Composite indexes idx_global_activities_parent_lookup and idx_campaign_recipients_lead_lookup with single-pass LEFT JOIN aggregations.
  • Pillar 3 — Active-View CQRS SQL Gating: 30s cached sidebar counts and strict active-view query isolation in blueprints/operations.py.
  • Pillar 4 — Server-Side Jinja DOM Pruning & Externalized JS: Prunes inactive views via {% if active_view == '...' %} and externalizes /static/js/backoffice_operations_core.js, shrinking HTML from 3.3 MB to <150 KB.
  • Pillar 5 — Sub-150ms Tab Switching: Verified across all 6 core departments (23–78 ms warm).

4.0 Part III: The Permanent 5-Layer Enterprise Phone, Tablet & Adaptive Data-Table Standard (v1.2.0 / BUG-135–BUG-137)

  • Layer 1 — App-Shell & Navigation Compaction: Enforces max-width: 100vw; overflow-x: hidden, single-bar phone headers (52px), touch-swipe navigation ribbons (.sigma-nav-ribbon), and an off-canvas QMS Manual drawer ([☰ Manual Sections & Search]).
  • Layer 2 — KPI & Multi-Column Grid Breakpoints: Collapses 4-column and 3-column KPI scorecards into 2 columns on tablets (<= 1024px) and 2x2 compact cards on phones (<= 768px), and stacks split grids into 1 column on phones.
  • Layer 3 — Universal Adaptive Data-Table Engine (SigmaResponsiveTableEngine + MutationObserver): Global script /static/js/sigma_responsive_engine.js automatically binds <thead><th> headers to <td data-label="..."> across all 28 tables, converting wide tables into 2-column CRM Touch Cards on phones (<= 768px) with a persistent [Cards | Table] switcher and single-sticky-column momentum scroll on tablets (768px–1024px).
  • Layer 4 — Touch Form Ergonomics & Cross-Device Column Sync: Enforces font-size: max(16px, 1rem) !important on mobile inputs, 92dvh safe-area modals, and PostgreSQL "UserUiPreferences" (Migration 045) cross-device column sync.
  • Layer 5 — Permanent Auto-Injection & 15-Test Regression Gate: Auto-injected on all HTML responses via main_app.py @app.after_request and verified by scripts/test_web_performance_rack_14.py (15/15 passing).
