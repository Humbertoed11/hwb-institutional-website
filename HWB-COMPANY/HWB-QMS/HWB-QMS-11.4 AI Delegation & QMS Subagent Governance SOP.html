Standard Operating Procedure: AI Delegation & QMS Subagent Governance

1.0 Purpose

This document standardizes the process for dividing work between AI agents. To maximize efficiency under our Minimization Mandate, repetitive administrative tasks (such as document formatting, file drafting, and index cataloging) are delegated to a specialized helper subagent. This frees up the Systems Architect's time to focus on complex coding, while maintaining a strict double-check process to ensure zero errors.

2.0 Scope

This protocol applies to all automated task delegation, helper agent creations, document modernizations, and manual updates performed inside our workspace.

3.0 Operational Roles & Responsibilities

  • George (Systems Architect / Lead Auditor): Sets strict safety limits, defines the helper agent's tasks, and performs the final Six Sigma quality check on all completed files.
  • QMS Editor Subagent (The Helper Agent): A highly focused writing assistant that copies templates, formats text, translates legacy documents into everyday words, and compiles the document index catalog.
  • CEO (Humberto Dominguez): The ultimate approval authority for all documents and system configurations.

4.0 Safety Limits (Safeguards)

To protect the security and reliability of our web application, the helper agent operates under strict boundaries:

  1. No Core Access: The helper agent is strictly prohibited from modifying core application routing (main_app.py), environment settings (.env), or database connections without direct written instruction and active audit by George.
  2. Sandboxed Staging: All drafted files must reside in standard QMS staging folders before compiling. No files may be published directly to live production without George's signature.

5.0 Step-by-Step Procedures

5.1 Task Assignment and Summoning

When an outdated Markdown document needs to be modernized to HTML, George will summon the helper agent using these steps:

  1. Define a sandboxed workspace for the helper agent, inheriting the standard system mandates and roles.
  2. Instruct the helper agent to parse the target outdated Markdown document, translate all technical jargon into clear Everyday Words, and format it exactly using the clinical sop_template.html structures.
  3. Direct the helper agent to save the completed HTML file under HWB-COMPANY/HWB-QMS/ and add the corresponding entry to HWB-QMS-7.5 Master SOP Index.html.

5.2 The Six Sigma Zero-Defect Audit

Once the helper agent finishes drafting and compiling, George must conduct a thorough quality inspection:

  1. Vocabulary Verification: Read the drafted text to verify it is written in Everyday Words suitable for a 20-year-old manager (no jargon, no academic phrasing).
  2. Layout Integrity Check: Inspect the HTML syntax. Ensure that all divs, tables, and paragraphs are closed properly, and that border-radii and headers strictly respect our 2026 Polish Standard.
  3. Compilation Check: Verify that the QMS catalog compiles cleanly by running the migration script: 
    .venv_agent/bin/python scripts/migrate_sops.py
  4. Live Routing Test: Launch the development server and verify that the newly created document renders correctly in the browser without overlapping or slow loads.

6.0 Verification Checklist (Audit Log)

Before submitting any document to the CEO, George must confirm the following:

  • The helper subagent completed 100% of the formatting task successfully.
  • Everyday Words are used throughout the entire document body.
  • The dynamic links and index files were updated with zero errors.
  • The final product has been physically audited and signed off by George.
