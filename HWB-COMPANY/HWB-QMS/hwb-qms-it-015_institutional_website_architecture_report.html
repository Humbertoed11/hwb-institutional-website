1.0 Purpose

To formally document the finalized cloud-native architecture of the HWB Cleaning Services LLC institutional website and backoffice platform across Microsoft Azure Web App for Containers, Cloudflare Anycast Edge, and PostgreSQL 16.15.

2.0 Architectural Standard (SigmaFidelity™)

2.1 Container & Entry-Point Alignment

The application executes via main_app.py under Gunicorn (3 workers × 8 threads = 24 concurrent request slots, 45s timeout, 1,000 max-requests auto-recycle) inside an immutable Python 3.12 Docker container deployed via Azure Container Registry (sigmajanacr.azurecr.io).

2.2 Environment Parity

All file paths use dynamic root resolution, guaranteeing 100% parity between local Linux Docker (hwb_web_app + hwb_postgres_dev) and Azure Cloud Production (HWB-SIGMAJAN-PROD).

2.3 PostgreSQL 16.15 Database Sovereignty

All operational, CRM, bidding, workforce, and neural records reside exclusively in PostgreSQL 16.15 (84 public tables, pgvector 0.8.2, pg_trgm, and fuzzystrmatch):

  • Cloud Production: Azure Database for PostgreSQL Flexible Server 16.15 (sigmajan-server.postgres.database.azure.com inside Private Link VNet).
  • Local Development: hwb_postgres_dev (pgvector/pgvector:pg16, volume postgres_data_pg16).
