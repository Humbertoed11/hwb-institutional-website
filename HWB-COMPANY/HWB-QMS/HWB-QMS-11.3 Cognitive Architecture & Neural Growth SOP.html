Standard Operating Procedure: Cognitive Architecture & Neural Growth

1.0 Purpose

This document details the persistent digital brain of the SigmaFidelity™ system. It explains how our artificial intelligence systems store, retrieve, and learn from daily work using Monolithic Neural Cores and 1536-dimensional semantic embeddings in PostgreSQL. The system continuously makes itself smarter, faster, and more reliable without manual data entry.

2.0 Scope

This procedure applies to all autonomous systems, software agents, and developers operating across the HWB ecosystem. It governs all interactions between the developer terminal, the web backend, and the live PostgreSQL database.

3.0 The Enterprise Memory Hierarchy

To eliminate memory loss between sessions and prevent repeat mistakes, the system maintains five specialized memory cores inside PostgreSQL:

3.1 The Interaction Core (SigmaInteractionCore)

  • Role: Records the high-level goals and outcomes of every session.
  • Value: Complete traceability from the CEO's directive to final code impact.

3.2 The Self-Healing Mistake Registry (SigmaKnowledgeScars)

  • Role: The system's self-healing library. Stores every past bug, root cause, code fix, and preventative rule.
  • Vector Engine: Every entry is indexed with a 1,536-dimensional semantic embedding generated by Google Gemini.
  • Value: A mistake once fixed becomes a permanent rule forever.

3.3 The Active System State (SigmaSystemCore)

  • Role: Keeps track of live environment telemetry, connection pool status, and database lead counts.
  • Value: Guarantees 100% parity with HWB-SESSION-RECOVERY.md so the agent wakes up knowing exactly where work left off.

3.4 The Granular Execution Ledger (CliSteps & CliConversations)

  • Role: Stores every prompt, terminal call, tool action, and assistant response (currently over 97,000 steps).
  • Value: Total transparency and instant historical replay of any engineering task.

3.5 The Organizational Knowledge Base (sigma_kb)

  • Role: Ingests all company HTML Standard Operating Procedures and guides (over 4,000 documents).
  • Value: Gives agents instant access to company rules using English text search.

4.0 Enterprise Semantic Embedding Engine (core/services/embedding.py)

To achieve Fortune 500 cognitive capability, text is no longer indexed with simple text matching or hashes. The system uses a dedicated semantic engine:

  • Model: Google Gemini gemini-embedding-001 projected to 1536 dimensions to match the PostgreSQL pgvector schema.
  • Concept Clustering: Detects semantic relationships between related industry concepts (such as "custodial work" and "janitorial services") even when different words are used.
  • Zero-Latency Memory Cache: Caches frequent queries in an in-memory lookup table to answer repetitive searches in 0 milliseconds.
  • Deterministic Fallback: If the cloud API is temporarily unreachable or offline, the engine automatically falls back to a mathematical hash projection without crashing the application.

5.0 Automated Pre-Flight Memory Gate & Risk Audit

Before any major software change or database modification begins, the system must execute a pre-flight risk audit against past knowledge scars:

  • REST Endpoint: GET /api/v1/kb/preflight?q=<directive>
  • CLI Utility: python3 scripts/preflight_audit.py "<directive>"
  • How It Works: The tool performs a hybrid Reciprocal Rank Fusion search across all 145 scars. If a matching past mistake is found, the system immediately returns a GUARDRAILS_MANDATED status and lists the exact preventative rules that must be followed before code is written.

6.0 Managed Background Synchronization (core/services/task_queue.py)

To ensure that updating memory never slows down the website or API, synchronization is managed by an asynchronous background worker pool:

  • REST Endpoint: POST /api/v1/neural/sync (Returns HTTP 202 Accepted with a unique task ID).
  • Worker Engine: The job runs inside the EnterpriseTaskQueue, executing scripts/sigma_sync.py in the background with automatic retries.

7.0 Verification & Automated Regression Gate

  • All neural components are verified by scratch/test_enterprise_neural_network.py.
  • The test suite is integrated into the Master CI/CD Battery (scripts/run_all_tests.py), verifying all 8 test suites before deployment.
  • All 145 scars in SigmaKnowledgeScars must maintain valid 1536d embeddings.
