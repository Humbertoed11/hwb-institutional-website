4.0 Component Directory (Top-Down Architecture)

Use the standard names below when referencing sections or requesting modifications to layout components.

1. Utility Bar (Brand Header)

brand_header.html

The top horizontal command bar (60px height). Holds the active pulse brand logo, a centered search bar (HUD mode) or navigation links (QMS mode), the active project selector dropdown, user identity role tag, and the active session logout button.

Parent Files: brand_header.html, included in hud.html and mega_bar.html.

2. Navigation Sidebar (HUD Nav & QMS Sidebar)

sop_base.html & hud.html

Dual navigation models:
• HUD Navigation Bar: 70px icon-only vertical strip on the left containing links to toggle Map, Data panels, Tools, and the QMS Manual.
• QMS Sidebar Navigation: 320px list panel on the left containing the live SOP search engine, the dynamic pinned active queue, recently viewed history files, master index link, and department accordions.

Parent Files: sop_base.html (QMS) & hud.html (HUD `#hex-nav`).

3. Geospatial Map Viewport (Deck.gl Canvas)

hud.html (#map-view)

The core geographical display of the HUD. Combines a MapLibre GL dark-matter base canvas with a layer of Deck.gl. Implements active zoom layers, Resolution-11 grid cells, interactive hover tooltips, and clickable parcel targets.

Parent Files: hud.html (controls nested inside `#map-container`).

4. Tactical Control Panel (Stick Ledger Drawer)

hud.html (#stick-ledger)

A 380px vertical control deck on the right side of the HUD. Contains the rolling mechanical altitude odometer digits (height display), the altitude slider range control, map layer checkboxes, and live database ingestion audit simulators.

Parent Files: hud.html (Right-side control board drawer).

5. George Console (Terminal & Insight Panel)

hud.html (#george-console)

The horizontal console panel docked at the bottom of the HUD dashboard. It is split into two boxes:
• Terminal Log (Left): Streams operational process logs from the autonomous agent.
• Alpha Insight Panel (Right): Displays final evaluation summary text, zoning details, and Nimby risk highlights.

Parent Files: hud.html (Bottom console footer).

6. Document Viewport (QMS Content Area)

qms_shell.html (#sop-injection-point)

The primary documentation reader card. Feeds the HTML/Markdown files served from the database or files. Incorporates user pin triggers (Pin to Active Queue) at the top and back/next links at the bottom for chronological reading flow.

Parent Files: qms_shell.html, extends sop_base.html.

5.0 QMS Document Formats (Uniform Structure)

All departmental manuals and implementation plans must follow a single snippet card structure to prevent CSS leakage and layout degradation:

Indestructible QMS Template Format

Standalone HTML boilerplates (such as <!DOCTYPE html>, <html>, <head>, <style>, or <body> tags) are strictly prohibited. Documents must consist of a clean HTML block wrapping the content: 

<!-- QMS Document ID: HEX-SOP-X.X -->
<div class="sop-card">
    <!-- 1. DOCUMENT CONTROL META -->
    <div class="sop-meta">
        <div class="meta-unit"><span class="meta-label">Document ID</span><span class="meta-val">HEX-SOP-X.X</span></div>
        <div class="meta-unit"><span class="meta-label">Version</span><span class="meta-val">1.0.0</span></div>
        <div class="meta-unit"><span class="meta-label">Status</span><span class="meta-val" style="color: #16a34a;">● ACTIVE</span></div>
        <div class="meta-unit"><span class="meta-label">Author</span><span class="meta-val">George Bytes</span></div>
    </div>

    <!-- 2. DOCUMENT BODY -->
    <div class="sop-content-body">
        <h1>Standard Operating Procedure: <strong>Title</strong></h1>
        <p>Document text goes here...</p>
    </div>
</div>

Technical Ledger: front-end coding conventions

Every frontend component must comply strictly with the following constraints derived from HEX-SOP-4.2-ENTERPRISE-UI-STANDARD:

  • Typographic Restraint: Labels sit at precisely 4px vertical proximity, font-weight set to 500. Modals and titles are capped at 1.5rem (Semi-Bold).
  • Vertical Compression: All button controls must be compressed to a height between 32px and 40px. Larger button sizes are banned.
  • Border-Radius Hardening: Set a rigid cap of exactly 6px for inputs, buttons, and control sheets. Modal cards or main canvas sheets are capped at 1.25rem (20px).
  • Color Hierarchy: The user interface relies on structural material depth offsets using #020617, #0f172a, #000000, and #1e293b. High contrast colors are reserved for live pulses or status indicators.
