Standard Operating Procedure: Scout Brain™ (Lobe 11) - Pipeline Ingestion & Data Integrity

1.0 Purpose

To define the architectural standards and operational responsibilities of Lobe 11: Scout Brain™. Lobe 11 acts as the primary gateway and sanitization filter for all external data connections. It actively searches the internet for municipal databases, tests connection speeds, and checks data formats before allowing information to feed the other ten neural lobes.

2.0 Core Functions of Lobe 11

Lobe 11 isolates external web-scraping and API-probing routines from the core analytical databases. It performs three critical operations:

  1. Seek (Discovery): Scans county and municipal websites for new GIS shapefiles, ArcGIS REST endpoints, deed registries, and public contact directories.
  2. Connect (Probe & Monitor): Regularly pings registered sources to monitor connection latency and uptime. It flags offline endpoints before they cause system timeouts.
  3. Collect (Validation & Ingestion): Extracts raw data, validates the schema (checking coordinate systems, datatypes, and empty fields), and sanitizes inputs. Verified data is then passed to the target lobes (L1-L7).

3.0 Database Schema & Registry

Scout registries, connection statuses, and pipeline metrics are recorded in the PostgreSQL database under the public schema:


CREATE TABLE "HEX_Scout_Registry" (
    id SERIAL PRIMARY KEY,
    municipality_name VARCHAR(150) NOT NULL,
    department_name VARCHAR(150) NOT NULL,
    source_type VARCHAR(100) NOT NULL,
    endpoint_or_contact TEXT UNIQUE NOT NULL,
    scouting_status VARCHAR(50) DEFAULT 'Identified',
    latency_ms INTEGER,
    scouted_notes TEXT,
    last_scouted TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

4.0 Pipeline Ingestion Workflow

Before supplying data to target lobes, Lobe 11 runs a strict validation sequence:

  • Step 1: Connection Test. The crawler pings the endpoint. If connection latency is under 5,000ms, status is marked Active. If it fails, it is marked Offline / Needs Review.
  • Step 2: Schema Match. Validates that incoming JSON/GeoJSON columns match target databases. For example, verifying municipal shapefiles contain correct coordinates and zoning labels.
  • Step 3: Lobe Routing. Sanitized data is inserted into the respective database core (e.g. routing AADT traffic logs to L2 TxDOT Brain).

5.0 Daily Operational Integration

The scout engine is driven by three active background tasks:

  • scripts/HEX-PULSE-SCOUT.py: Runs daily to refresh connection statuses for target submarkets (Dallas, Tarrant, Denton, Collin, and Wise Counties). Results are exposed via the /api/v1/pulse/scout-summary API.
  • scripts/HEX-MINER-L11-TXDOT.py: Queries the TxDOT ArcGIS REST API for raw traffic volume data near coordinates and caches them inside the HEX_TxDOT_Staging table.
  • scripts/download_trerc_pdfs.py: Scrapes the Texas Real Estate Research Center (TAMU TRERC) reports and sitemaps to download monthly and quarterly PDF publications into the Research-docs/ folder.
