Standard Operating Procedure: Naming Convention & Architecture

1.0 Purpose

To define the clinical standards for file naming, directory structure, and URL optimization within the hex.local ecosystem. This ensures 100% traceability and future SEO dominance.

2.0 Internal ID Casing (Traceability)

All internal assets must be prefixed with HEX- followed by a department code and a sequential number.

  • SOPs: HEX-SOP-[Number]-[Descriptive-Name].html
  • Data Miners: HEX-MINER-[Source].py
  • Brain Components: HEX-LOBE-[Name].py

3.0 Public Alias Casing (SEO)

All public-facing files and URLs must be lowercase and use hyphens for word separation. No internal IDs should appear in public URLs.

  • Good: /manual/real-estate-zoning-guide
  • Bad: /manual/HEX-SOP-1.2-Zoning

4.0 Directory Architecture

  • /HEX-QMS/: Source HTML documents organized by ISO 9001 clauses.
  • /app/static/manual/: Compiled SEO-friendly fragments.

5.0 ISO 9001 Section Mapping

All QMS manuals and reports are stored in subdirectories that correspond to the ISO 9001:2015 clauses. The file paths and categories in the registry must align with this mapping:

ISO 9001 Clause HexGrowth Folder Database Category Document Prefixes
Clause 4: Context of the Organization /HEX-QMS/context/ 04 Context & Scope HEX-SOP-0.X
Clause 5: Leadership /HEX-QMS/leadership/ 05 Leadership & Governance HEX-SOP-1.X
Clause 6 & 7: Planning & Support /HEX-QMS/planning/ 06 Planning & Support HEX-SOP-2.X, HEX-IP-X.X, HEX-SOP-7.X
Clause 8: Operation /HEX-QMS/operations/ and /lobes/ 08 Operations & Development HEX-SOP-3.X to 6.X, HEX-LOBE-X.X

Clause 10: Improvement /HEX-QMS/evaluation/ 10 Improvement HEX-REPORT-12.0, HEX-REPORT-13.0
