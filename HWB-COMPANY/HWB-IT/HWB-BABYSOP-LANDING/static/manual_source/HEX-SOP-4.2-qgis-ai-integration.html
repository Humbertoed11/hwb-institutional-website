Standard Operating Procedure: QGIS AI Integration & MCP Orchestration

1.0 Purpose

To record and formalize research regarding the integration of Large Language Models with QGIS (Geographic Information System) using the Model Context Protocol. This protocol enables autonomous agents to interact directly with QGIS to run mapping operations, load layout layers, and compile spatial reports.

2.0 Core Integration Architecture

The system connects AI models to QGIS through two way communication channels:

  • Model Context Protocol Server: An MCP server runs locally, exposing QGIS Python API methods as tools that the AI model can execute.
  • JSON RPC Communication: Commands from the AI agent are translated into JSON RPC calls and sent to the QGIS python console port to execute scripts in the active QGIS session.
  • Dynamic Scripting: Rather than hard coding every mapping feature, the AI reads the active layer properties, generates custom python logic, and runs it to style map features or execute spatial queries.

3.0 Key Spatial Operations Supported

  1. Layer Loading and Styling: Loading shapefiles, raster maps, or GeoJSON layers, and applying color palettes based on criteria like land values or traffic metrics.
  2. Geoprocessing Tasks: Computing buffers, intersections, and hexagonal tessellations dynamically via the processing toolset.
  3. Layout Generation: Generating print layouts and exporting high resolution maps to files.

4.0 Applications to HEXGROWTH

Integrating QGIS automation into the HEXGROWTH workspace allows:

  • Automated Map Production: The accountability and reporting brains can automatically trigger QGIS in the background to render submarket maps for developer reports.
  • Visual Auditing: The scout brain can load new municipal zoning shapefiles into a QGIS canvas to run visual sanity checks before importing them to the PostGIS spine.
