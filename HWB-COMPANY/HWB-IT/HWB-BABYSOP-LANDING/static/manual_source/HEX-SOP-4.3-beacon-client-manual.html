Master Operating Procedure: Opportunity & Alarm Beacons

Scope: Details the technical layout, client control interfaces, and backend endpoints governing three dimensional altitude beacons and the dynamic general alarm beacon.

1.0 Beacon Hierarchy & Altitude Tiers

The system visualizes spatial anomalies and development targets using vertical markers mapped to specific elevation layers:

  • Sky Tier (Altitude > 100,000 feet): Represents metropolitan hubs (such as DFW Hub or Wise County Hub) that indicate aggregate regional zoning variance capacities and municipal debt.
  • Clouds Tier (Altitude between 25,000 and 100,000 feet): Represents target corridors and logistics spurs (such as Northwest Highway or Decatur Growth path) optimized for shipping egress.
  • Ground Tier (Altitude <= 25,000 feet): Renders parcel outlines, PostGIS cell scores, and neighborhood opposition buffers. Beacons are hidden at this zoom level to maintain visibility.

2.0 Dynamic General Alarm Beacon

The client can assign one of the following categories and corresponding colors to the alarm beacon:

3.0 Client Interface Controls

The customizable options are exposed directly in the sidebar panel:

  1. Category Dropdown: Elects the alert class to write to the database (Security, Zoning, Traffic, or Power).
  2. Color Selector: Changes the visual RGB tint of the pulsing circle on the Deck.gl map layer.
  3. Update Button: Sends an asynchronous network request to commit the settings and update the map layer in real time.

4.0 API Endpoint Integration

The client controls communicate with PostgreSQL through two primary Flask routes:

  • GET /api/v1/beacons: Returns a list of all active beacons including coordinates, altitude tier, description, color string, and category.
  • POST /api/v1/beacons/alarm: Receives a JSON payload containing the chosen category and color, updating the corresponding record in the database.
