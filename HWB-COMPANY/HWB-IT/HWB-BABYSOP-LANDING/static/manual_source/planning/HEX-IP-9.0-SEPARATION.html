HEXGROWTH Azure Separation Plan

This implementation plan outlines the architectural steps necessary to achieve complete separation of HEXGROWTH assets from legacy parent entities inside the Microsoft Azure Cloud. This ends the sharing of database servers, container registries, web app hosting plans, and DNS records to secure institutional boundaries for independent investor pitches.

⚠️ STRATEGIC MANDATE

Moving from shared resources (Path B) to total isolation will terminate the $0/month hosting cost arrangement. Provisioning dedicated services will introduce active hosting and database server charges to HEXGROWTH. CEO approval is required prior to resource creation.

Required Actions

1. Azure Directory & Subscription Separation

  • Current State: HexGrowth runs within legacy parent active subscription (d778faac-02a4-4d74-9881-199994f2bd98).
  • Target Action: Establish a dedicated Azure Subscription (e.g., HEXGROWTH-Production-Subscription) or a separate Microsoft Entra ID Tenant to isolate billing, access, and directories.
  • Resource Group: Provision a dedicated Resource Group HEXGROWTH-Production-RG.

2. Database Server Separation

  • Current State: HexGrowth shares the active database instance (sigmajan-server.postgres.database.azure.com).
  • Target Action: Provision a dedicated Azure Database for PostgreSQL Flexible Server (e.g., hexgrowth-db-server.postgres.database.azure.com) with PostGIS extension.
  • Migration Step: Perform a spatial pg_dump from the active container and restore it to the isolated production database.

3. Private Registry & Deployment Isolation

  • Current State: Deployments pull images from legacy parent private registry (legacy-parent-registry.azurecr.io).
  • Target Action: Provision a dedicated Azure Container Registry (ACR) (e.g., hexgrowthprodacr.azurecr.io).
  • CI/CD Update: Update GitHub Action secrets and workflow targets to push builds exclusively to the new registry.

4. Web Application hosting

  • Current State: HexGrowth shares the App Service Plan and runtime container with BabySOP.
  • Target Action: Provision a dedicated Linux App Service Plan (e.g., hexgrowth-linux-asp) and run a separate Azure Web App for Containers instance (e.g., hexgrowth-web-app).

5. Custom Domain & DNS Configuration

  • Current State: Subdirectory routing via babysop.com/hexgrowth.
  • Target Action: Transition completely to a dedicated domain (e.g., hexgrowth.com or hexgrowth.app). Bind this custom domain to the new App Service with SSL certificates.

6. Codebase Separation

  • Current State: Intermingled directory references under babysop/clients/.
  • Target Action: Completely separate the git repositories. Detach the codebase into a dedicated repository: github.com/hexgrowth/hexgrowth-core.
