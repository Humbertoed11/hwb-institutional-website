Standard Operating Procedure: Reporting Architecture

1.0 Purpose

To define the flow of diagnostic data, QMS audits, and real estate market valuations into the Terminal HUD.

2.0 Data Flow

  1. Lobe Update: External miners write normalized Alpha scores to the Postgres DB tables.
  2. JSON Assembly: The Flask backend server dynamically loads table entries and compiles GeoJSON parameters.
  3. Viewport Rendering: The React/Deck.gl HUD maps the compiled indicators as visual indicators.

3.0 Formatting Standards

Reports and document logs displayed within the HUD viewport must avoid plain red or blue styles, utilizing HSL palettes, smooth dark gradients, and clean borders (minimum depth effects).

System Synchronization

Any updates to files inside the QMS manual folder must automatically sync using the Persistence Protocol to reflect in the HUD Index search.
