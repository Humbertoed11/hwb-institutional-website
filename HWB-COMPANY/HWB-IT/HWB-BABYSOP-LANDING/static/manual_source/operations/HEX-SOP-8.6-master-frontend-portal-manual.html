Master Operating Procedure: Frontend Portal & Viewport Specifications

Scope: Establishes global constraints and layout specifications for the project management hub, header branding systems, viewport switchers, and administrator dashboard layouts (Layer 3 visual portals).

1.0 Purpose & Architecture Overview

This document details the operational structures and interface layout grids for the client-facing portals:

  • Workspace Portal (/projects): A project management dashboard allowing developers to add and edit target project sites, review active KPIs, delete database records, and select viewport views.
  • Viewport Switcher: A dropdown selector in headers that allows developers to toggle between standard map views and tactical console layouts.
  • Backoffice Control Panel (/admin/control-panel): A system administration panel for VPs and auditors to override baseline rates, toggle operational brain lobes, ping ingestion targets, and verify system dependencies.

2.0 Layout Structure & Header Standardization

To secure vertical space for geospatial scanning, the system standardizes navigation headers on Option A: The Shared Component Model (60px height):

  • HUD Configuration: Renders a 60px height header with a centered geographic search input field, logo, active project picker dropdown, and session detail clusters.
  • QMS Document Shell Configuration: Renders a 60px height header, replacing the search input with QMS directory navigation links while keeping the branding and session components identical.
  • Double-Layer Headers: Double-layer navigation bars (110px height, such as mega_bar.html) are prohibited on HUD viewports to prevent layout clutter and canvas scaling errors.

3.0 Workspace Project Ingestion & Switcher Logic

3.1 Project Form Ingestion

New workspace projects are committed via the outlined form inside the Workspace Portal. Form inputs must sit at a tight 4px vertical proximity to labels. Upon submission, the client calls: POST /api/v1/projects. The backend saves target coordinates, budgets, target internal rate of return (IRR), and focal diagnostic lobes to the HEX_Projects database table. The viewport cache is re-compiled upon page reload.

3.2 Viewport Switcher

Users can select one of two viewport designs to launch on an active project:

  1. Standard HUD: Focuses on graphical visual assets, pulsing beacons, map layers, and simulation sequences.
  2. Hex-Terminal: Renders a dense, keyboard-driven dashboard with a pro-forma calculator, real-time transaction feeds, and console commands.

4.0 Backoffice Control Panel Specifications

The admin portal allows direct control over operational features using standard design guidelines:

  • Parameter Settings: Updates baseline variables (such as interest rates, cap rates, permit latency days, and transit speed targets) stored in the database.
  • Lobe Activity Grid: Displays active cards for the 11 operational brains, detailing active weights and toggles to enable/disable each lobe.
  • Interactive Dependency Flowchart: SVG/Mermaid flowchart displaying the system's live logic flows. Disabled lobes are automatically dimmed and drawn with dashed outlines to warn of broken dependencies.
  • Ingestion and Audit Management: Includes tabs to add/remove ArcGIS GIS endpoints (with a built-in ping latency checker) and edit the 100 system audit checks.

4.1 Lobe 10 Report Compiler Overrides

To output JBREC-compliant valuation and feasibility report packages, the backoffice administrator interface exposes specific controls over the Lobe 10 generation pipeline:

  • Economic Assumption Overrides: Real-time editing of variables (Interest Rate, Cap Rate Baseline, and Construction Cost Index) which dynamically calculate monthly costs and qualifying incomes.
  • Project Target Values: Direct controls to edit project boundaries, target IRR percentage anchors, and lot size layouts in the HEX_Projects registry.
  • Lot Sizing & Multiplier Profiles: Tables to manage lot dimensions and their base pricing multipliers (ranging from 0.70 to 1.40).
  • Amenity Premium Variables: Toggle switches and percentage value additions for premium community features (e.g., crystal lagoons, trail parks) to calculate value premiums.
  • Active Lobe Weight Verification: A summary showing the active system weights used during compiling to ensure total audit traceability.
  • Customizable Markdown Editor: An inline text editor to write, save, and insert the executive summary directly into the client's report package.
