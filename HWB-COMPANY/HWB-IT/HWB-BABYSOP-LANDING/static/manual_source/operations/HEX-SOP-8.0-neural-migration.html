Standard Operating Procedure: Neural Migration

1.0 Purpose

To define the procedures for updating and migrating database schemas across the HEXGROWTH multi-lobe infrastructure without causing service interruption or data loss.

2.0 Schema Invalidation Rules

  1. Audit Before Migration: Run standard diagnostics to verify connection string parameters and write-permissions before making schema changes.
  2. Backward Compatibility: Never drop or rename columns currently queried by active production components. Use additions or non-breaking mutations.
  3. Dynamic Fallbacks: If PostgreSQL extensions (such as pgvector) are missing, fallback logic must be programmatically defined (e.g. converting vector(1536) to DOUBLE PRECISION[]).

3.0 Execution Protocol

All database migrations must execute through isolated setup scripts (such as HEX-SCHEMA-INIT-CORES.py) rather than manual console queries to ensure repeatability and tracking.

The Minimization Mandate

Schema changes must occur during low-traffic slots (02:00 - 04:00 UTC) and must log their initial and final states to HEX_Telemetry.
