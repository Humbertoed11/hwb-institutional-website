Standard Operating Procedure: The Miner (Layer 2)

1.0 Purpose

To define the operational standards for the HEXGROWTH Miner. The Miner is a set of autonomous Python workers responsible for the 24/7 extraction, cleaning, and ingestion of raw data from external APIs and municipal records into the PostGIS Spine.

2.0 The Extraction Cycle

  1. Wake-up: Triggered by a cron-job or Azure Function.
  2. Fetch: Query external sources (FEMA, TxDOT, NASDAQ, etc.).
  3. Map: Use the h3 library to assign data to specific Resolution 11 hexagons.
  4. Refine: Convert raw values (e.g., "12,000 cars/day") into normalized Alpha Scores (0-10).
  5. Ingest: UPSERT the refined data into the corresponding Lobe table in Postgres.

3.0 Data Normalization (The Alpha Scale)

To ensure the 7 Brains can "vote" equally, all data must be refined to a 0.0 to 10.0 scale:

  • 10.0: Optimal Opportunity / Zero Risk.
  • 5.0: Neutral / Average.
  • 0.0: Extreme Risk / Fatal Defect (No-Go).

4.0 Integrity Mandates

  • No Stale Data: Every ingested record must have a source_timestamp.
  • Clinical Cleanup: Null or malformed API responses must be logged to HEX_KnowledgeScars and ignored.
The Minimization Mandate

The Miner must be 100% autonomous. Human intervention is only permitted for the Ranger Brain (Field Overrides).
