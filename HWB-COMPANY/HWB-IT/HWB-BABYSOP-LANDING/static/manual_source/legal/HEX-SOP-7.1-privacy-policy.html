Standard Operating Procedure: Data Privacy & Portfolio Security (ISO 8.2)

Purpose: Establishes the standard data privacy controls for protecting user profile information, search logs, and developer portfolios from unauthorized access or corporate espionage.

1.0 Password & Session Encryption

To protect access credentials, the platform enforces the following cryptographic standards:

  • Password Hashing: Passwords must be hashed using PBKDF2 with a SHA256 fallback wrapper inside the database. Cleartext storage is prohibited.
  • Session Validation: Active user sessions are encrypted using the application server secret key (SECRET_KEY) and saved inside secure, HTTP-only cookie wrappers.

2.0 Portfolio Data Isolation

Developer search histories, parcel watchlists, and score scenarios are sensitive intellectual assets. They must be stored in database tables with row-level constraints:

  • Access Isolation: Spatial query requests are restricted to the logged-in user account. The API router must validate that the requested portfolio matches the active session ID.
  • Logging Restraint: Spatial bounding box lookups are cached locally to optimize speed, but logs containing exact street addresses or zoom coordinates must be cleared after 24 hours.

3.0 Regulatory Compliance (GDPR/CCPA)

While serving commercial real estate developers, the platform aligns with key data protection frameworks:

  • Data Deletion: Users hold the right to request permanent deletion of their search logs and saved scenarios. Database commands must execute a hard delete of matching user records.
  • Audit Logs: Any access to database tables containing search histories by administrators must log the action, timestamp, and purpose.
Security Warning: Any attempt to bypass the login gate or query tables directly without an active session token will trigger an automated IP ban.
