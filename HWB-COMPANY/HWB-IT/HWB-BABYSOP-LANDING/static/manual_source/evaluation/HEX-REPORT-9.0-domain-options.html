HEXGROWTH: Domain & URL Naming Options (06/03/2026)

This report outlines the proposed web address (URL) options for referencing the HEXGROWTH platform under the existing company domain name babysop.com. This allows the team to share the proof of concept (POC) with investors safely and professionally.

1.0 System Context

The web application is currently running as hex-babysop-landing on Microsoft Azure. The domain name babysop.com is already verified and mapped to this application. Below are three methods for adding the hexgrowth name into the web address structure.

2.0 Naming Options

  • Option A: Subdomain Routing (Most Professional)
    Example: http://hexgrowth.babysop.com or http://hex.babysop.com
    How it works: This creates a separate web address prefix. It shows investors that HEXGROWTH is a distinct business division.
    Technical Setup: A DNS CNAME record must be added at the domain registrar to point hexgrowth.babysop.com to hex-babysop-landing.azurewebsites.net, followed by adding the custom domain inside the Azure portal.
  • Option B: Subdirectory Routing (Easiest to Deploy)
    Example: http://babysop.com/hexgrowth or http://babysop.com/hex
    How it works: This places the map tool in a sub-folder under the main website. It requires no DNS changes.
    Technical Setup: A route handler must be registered in the application code main_app.py (e.g., mapping @app.route('/hexgrowth') to the HUD template).
  • Option C: Standalone Domain (Premium Branding)
    Example: http://hexgrowth.com or http://hexgrowth.app
    How it works: A separate domain is purchased specifically for the product. This offers the cleanest branding but has a small extra cost.
    Technical Setup: Buy the domain from a registrar and bind it as a custom domain to the Azure web application.

3.0 Reference Rules

All public URL paths must follow the lowercase naming standard specified in HEX-SOP-1.0-NAMING. Standard folder paths (like /manual/ or /hud/) must be lowercase and use hyphens for separation.
