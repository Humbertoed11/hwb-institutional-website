HEXGROWTH: Master Specification Comparison (06/03/2026)

A comparative analysis of the active local HEXGROWTH codebase against the specifications outlined in the master reference document.

1.0 Product Vision & Status

The local application is currently in the prototype stage, focused on a local grid in Plano, Texas. The master document specifies a nationwide parcel intelligence system with live data feeds and automated report generators.

2.0 Architectural Gaps

  • Backend API: The current system uses Flask. Production specification requires a migration to FastAPI.
  • Frontend UI: The current system uses simple template files. Production specification requires a Next.js framework.
  • Caching: The current system has no query caching. Production specification requires a Redis layer.

3.0 Ingestion & Scoring Gaps

  • Parcel Grid: The current grid uses calculated H3 hexagons. The master spec requires 160 million real-world parcels via the Regrid API.
  • Infrastructure Scoring: Current scores are procedurally calculated based on Plano highway coordinates. The master spec requires live feeds for electric substations, sewer lines, and fiber cables.
  • Entitlement & Risks: No voting data ingestion or flood hazard layers have been connected.
