Standard Operating Procedure: Disaster Recovery and Data Restoration

1.0 Purpose & Continuous Recovery Mandate

This procedure defines the protocol for recovering company operations, databases, application containers, cryptographic keys, and AI agent brains following a hardware failure, data corruption event, or cloud disruption. In strict adherence to our Continuous Recovery Mandate, this SOP is updated immediately following any new software installation, container dependency upgrade, or database migration.

2.0 Scope

Applies to all Linux host machines, Docker containers, PostgreSQL databases, Microsoft 365 integrations, and AI agent state directories across HWB Cleaning Services LLC.

5.0 Step-by-Step Restoration Procedures

5.1 Cold Server Rebuild (Total Catastrophe Recovery)

  1. Clone primary repository: git clone https://github.com/Humbertoed11/gemini_projects.git
  2. Restore frozen .env file from the Vault Guardian archive into HWB-COMPANY/HWB-IT/HWB-IT-WEBSITE/.env.
  3. Execute master startup sequence: bash scripts/startup_master.sh
  4. Verify Docker containers are healthy: docker ps

5.2 Database Restoration & Peter Unified 3-Command Recovery Standard (v2.0.0)

Strictly scoped to /home/humbertoed/gemini_projects, scripts/peter_sentinel.py (v2.0.0) provides the unified 3-command local recovery workflow:

  1. Create Pinned Pre-Change Checkpoint: python3 scripts/peter_sentinel.py checkpoint --label <name> — Captures an owner-only (chmod 600) PostgreSQL 16.15 custom-format dump (pg_dump -Fc), chmod 600 .env secret file, and complete active HWB code/QMS bundle (hwb_code_bundle.tar.gz) inside backups/checkpoints/<name>/ with SHA256SUMS.txt (exempt from 24-hour auto-purge). Automatically test-restores the dump into temporary database hwb_peter_verify_tmp, confirms 80+ public tables, and drops the temporary database immediately.
  2. Execute Code-Only or Full Staging-Swap Rollback: python3 scripts/peter_sentinel.py rollback --label <name> [--code-only | --full] — --code-only restores the pinned code and QMS bundle and restarts hwb_web_app; --full restores the pinned PG16 dump into a clean staging database (hwb_restore_stage) first, briefly stops hwb_web_app and hwb_agent_worker, swaps hwb_dev_db cleanly so open database sockets and "SecurityAuditLogs" WORM triggers never block recovery, restarts both containers, and confirms all 4 supervised worker processes via docker top hwb_agent_worker.
  3. Verify Hourly Backup Health & Checksum Integrity: python3 scripts/peter_sentinel.py verify — Confirms backups/latest/hwb_dev_db.dump is under 90 minutes old, non-empty, locked to chmod 600, and matches hwb_dev_db.dump.sha256, recording Peter's verification status in PostgreSQL "AIEmployeeHeartbeat" and "SecurityAuditLogs".
  4. Run Post-Restore Quality Gates: Verify curl -s http://127.0.0.1:5000/api/v1/db-audit, python3 scripts/tessa_regression_suite.py, and python3 scripts/yamamoto_bid_test_suite.py.

5.3 The Panic Button (Working Tree Clean Reset)

If local uncommitted code disrupts container execution, run python3 scripts/peter_sentinel.py rollback --label <name> --code-only (preferred) or git reset --hard HEAD && git clean -fd followed by docker restart hwb_web_app.

5.4 Three-Layer Sovereign Backup & Two-Tier Disaster Recovery Architecture (v3.1.0 — 11/12/2026)

Legacy sigma-peter.service (15-minute daemon) and /mnt/c/.../OneDrive cross-OS 9P backups are permanently retired (BUG-173 / SO-SCAR-023) because 9P file locking hangs WSL2. Production continuity operates across three sovereign layers:

  • Layer 1 — Hardened Hourly Native ext4 Snapshots & Peter Checkpoints: scripts/hwb_hourly_backup.sh runs via Linux cron at :00 every hour, writing 24-hour rolling pg_dump -Fc PostgreSQL 16.15 binary snapshots with chmod 600 owner-only permissions and .sha256 checksums into backups/hourly/ and backups/latest/ (hwb_dev_db.dump + hwb_dev_db.dump.sha256), paired with scripts/peter_sentinel.py (v2.0.0) pinned vaults in backups/checkpoints/.
  • Tier 1 Rescue (PC Intact, WSL2 / Ubuntu Hung or Broken): Open the Out-of-Band Windows Antigravity Rescue Cockpit at C:\wsl-backup\SuperGeorge-Rescue (configured in Request Review / ASK mode with zero L:\ Linux drive dependency so Windows never freezes) or run PowerShell C:\wsl-backup\restore-system.ps1.
  • Tier 2 Bare-Metal / Lost PC Nuclear Restore (Grab-and-Go USB Drive D:\):
    1. Run wsl --install -d Ubuntu in Administrator PowerShell and reboot.
    2. Install offline installers from D:\Installers\: Docker Desktop Installer.exe (Docker Hub User: hdominguez11, Email: hdominguez@hwbcleaning.com; enable Settings -> Resources -> WSL Integration -> Ubuntu after Step 3) and Antigravity-x64.exe (Google login: humbertoed@gmail.com).
    3. Double-click D:\restore-system.bat (restores the Ubuntu WSL2 image from D:\2026-data-backup-ubuntu\ubuntu-full.tar, applies .wslconfig [12GB RAM / 6 CPUs], and verifies /home/humbertoed/gemini_projects and external sibling workspaces).
    4. Open Windows Antigravity -> File -> Open Folder -> D:\SuperGeorge-Rescue (or connect to WSL Ubuntu once restored) and boot the local HWB container stack (127.0.0.1:5000).
