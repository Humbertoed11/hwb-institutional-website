Standard Operating Procedure: Terminal Interaction & Reporting Architecture

1.0 Purpose

To define the mandatory frameworks for visual organization and data reporting within the Antigravity CLI. This ensures the CEO (Humberto Dominguez) receives high-fidelity information in a consistent, industrial-grade format.

2.0 Interaction Model Hierarchy

The agent MUST select the appropriate model based on task complexity:

2.1 The Topic Model (Primary Interface)

  • Use Case: Multi-turn codebase modifications, complex audits, and migration tasks.
  • Visuals: Stylized terminal boxes generated via update_topic.
  • Requirements: Must include a 1-sentence "Strategic Intent" and a 5-10 sentence "Summary."

2.2 The Workflow Model (Gemini-Kit)

  • Use Case: Standardized engineering cycles (Feature, Refactor, Review).
  • Mechanism: kit_run_workflow.
  • Visuals: Step-by-step cycle tracking (Plan -> Act -> Validate).

2.3 The Orchestration Model (Sub-Agents)

  • Use Case: Batch processing, exhaustive file searches, or specialized "Silo" tasks.
  • Mechanism: invoke_agent (e.g., Planner, Scout, Coder).
  • Visuals: Consolidated "Executive Handoff" reports in the terminal.

2.4 The Walkthrough Model (Institutional Capital)

  • Use Case: Final session handovers and architectural state changes.
  • Mechanism: Generation of walkthrough.md or .html artifacts.
  • Visuals: Persistent files designed for browser review; linked to the SigmaWalkthroughs database table.

2.5 The Direct Execution Model (Velocity)

  • Use Case: Quick inquiries, single shell commands, or minor text edits.
  • Visuals: Standard Markdown output; zero administrative boxes.
Technical Logic

Antigravity CLI automatically imports these models as "Interaction Synapses" from our 4-Tier Memory. 100% Alignment is required for all agent responses.

3.0 Reporting Standards

Regardless of the model chosen, all reports must adhere to the High-Impact Protocol:

  1. Objective: What is the value focus?
  2. Strategy: How will we achieve speed/scale?
  3. Execution: What specific technical steps are being taken?
  4. Assets: What code or prompts were generated?
  5. Scale: How is this being systemized for the future?

4.0 Verification (Zero-Defect Check)

  • Did the agent use the 3rd person clinical perspective?
  • Is the report authored in "Everyday Words" (20-year-old manager level)?
  • Is the summary high-density and free of conversational fluff?
