Backend Architecture & Logic

This manual documents the Institutional "Brain" of HWB. It maps the server logic, database connections, and agentic intelligence that powers our industrial operations.

1.0 What this is for

The backend is where all our data is processed and saved. These rules ensure that our databases, login systems, and AI agents always work together without crashing the server.

2.0 The Vital Organs (Core Files)

[ROUTING]
Identity: The System Engine
Physical Path: HWB-COMPANY/HWB-IT/HWB-IT-WEBSITE/main_app.py
Logic: Handles all URL requests (Routes), User Login, and Lead Ingestion.
[DATA]
Identity: Persistence Layer
Physical Path: core/services/database.py
Logic: Standardizes the connection to PostgreSQL and SQLite. Ensures "Source of Truth" data integrity.
[INTELLIGENCE]
Identity: Agent Logic
Physical Path: core/agents/
Logic: Houses the personalities and capabilities of George (Architect) and Silas (CRM).

3.0 Data Integrity (Tier 6)

All backend decisions must be logged to the Operational Telemetry database.

Tracking Table: "SigmaTelemetry"
Logging Tool: scripts/push_telemetry.py
Standard: Log every major route change or database schema update.

4.0 Secret Management

⚠️ MANDATE 0.0 (Credential Protection)

  • Never commit database passwords or API keys to the repository.
  • All secrets must stay inside the .env file (located at Project Root).
  • Verify .gitignore includes .env before every push.

5.0 Backend Health Check

To verify the backend is healthy, run these 3 commands:

1. docker logs hwb_web_app --tail 20 (Check for Crashes)
2. flask routes (Check for Missing Paths)
3. psql -c "\dt" (Check for Database Persistence)
