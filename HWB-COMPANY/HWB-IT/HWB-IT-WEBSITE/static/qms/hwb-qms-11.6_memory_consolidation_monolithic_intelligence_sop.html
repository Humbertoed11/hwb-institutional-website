Standard Operating Procedure: Memory Consolidation & Monolithic Intelligence

1.0 Purpose

To define the mandatory procedure for eliminating cognitive and data redundancy within the SigmaFidelity™ memory architecture. This SOP transitions the system from fragmented logs and registries to a high-velocity Monolithic Neural Core, optimized for the Antigravity CLI.

2.0 Cognitive Consolidation Targets

The following mental processes are designated for immediate consolidation to prevent "Three-Headed Clerk" syndrome:

2.1 The Interaction Core (Merging Audit Logs)

  • Action: Merge agent_telemetry (technical) and SigmaInteractionLog (high-level).
  • New Structure: SigmaInteractionCore.
  • Mandate: A single SQL write must capture both the CEO's prompt and the agent's raw technical execution data.

2.2 The Knowledge Scars (Merging Failure Registries)

  • Action: Merge SigmaProblems (bugs) and SigmaIntuition (rules/mistakes).
  • New Structure: SigmaKnowledgeScars.
  • Mandate: A single table serves as the "Neural Synapse" for risk auditing, tracking an error from discovery to hardened prevention rule.

2.3 The System Core (State Parity)

  • Action: Force 100% parity between SigmaState (Postgres) and HWB-SESSION-RECOVERY.md (Git).
  • New Structure: SigmaSystemCore.
  • Mandate: Antigravity MUST treat the SQL state as authoritative, falling back to Markdown only during cold-boot infrastructure failures.
Technical Logic

Consolidation reduces database I/O, minimizes context bloat in the Antigravity brain, and ensures that cross-agent orchestration operates from a single source of truth.

3.0 Transition Procedure

  1. Pre-Migration Backup: Create a full SQL snapshot (pg_dump).
  2. Table Creation: Draft and execute SQL migrations for the new "Core" tables.
  3. Data Ingestion: Transfer legacy records from fragmented tables into the monolithic cores.
  4. Logic Redirection: Update all ingestion scripts (e.g., ingest_walkthrough.py) to point to the new cores.
  5. Validation: Run a "Neural Consistency Audit" to ensure zero data loss.

4.0 Verification (Zero-Defect Check)

  • Are there any remaining writes to deprecated tables (telemetry, intuition)?
  • Does the Pre-Flight Risk Audit correctly query the SigmaKnowledgeScars core?
  • Is the Interaction Core capturing 100% of technical telemetry?
