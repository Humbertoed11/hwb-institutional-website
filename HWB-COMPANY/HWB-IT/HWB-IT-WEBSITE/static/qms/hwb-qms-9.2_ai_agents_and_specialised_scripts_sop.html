Standard Operating Procedure: AI Agents & Specialized Automation Scripts

1.0 Purpose

This standard operating procedure defines the execution standards, process supervision rules, and operational boundaries for all autonomous AI agents and specialized background scripts operating within the SigmaFidelity™ infrastructure. The goal is to eliminate manual administration, enforce zero-defect data processing, and maintain continuous platform availability.

2.0 Scope

This procedure applies to all background processes, supervisor daemons, cron tasks, and CLI automation utilities executed inside the hwb_agent_worker container, the web application container, and the Linux host environment.

4.0 Daemon Supervision & The 4-Tier Zero-Defect Mandate

  1. Worker Supervision: All background agent daemons running inside hwb_agent_worker must be registered in the AGENTS array of worker_launcher.py.
  2. Idempotency: Every script must be completely idempotent. A restart or redundant execution cycle must never duplicate database records, corrupt ongoing transactions, or clobber reconciled financial data.
  3. Strict Output Staging: Automated outreach scripts are strictly prohibited from dispatching live communications directly to prospective clients. All outbound proposals must be staged into PendingOutbox using the HWB-COM-001 official letterhead for CEO review and approval.
  4. Error Logging: If any background script encounters an unhandled exception or operational failure, the event must be immediately recorded to docs/PROBLEMS-TO-SOLVE.md per our institutional error logging mandate.
  5. 4-Tier Automated Quality Gate: Prior to any production deployment, the codebase must pass all 4 testing tiers with a 100% score:
    • Tier 1: Tessa Platform Regression Suite (11 modules) — python3 scripts/tessa_regression_suite.py
    • Tier 2: Yamamoto Moto AI Estimator Suite (8 modules) — python3 scripts/yamamoto_bid_test_suite.py
    • Tier 3: Site Security Rack #9 Suite (11 modules) — python3 scripts/site_security_audit.py
    • Tier 4: Enterprise Bot Defense Battery (6 modules) — python3 scripts/bot_defense_test_suite.py
  6. Enterprise Context Resolver & Anti-Narrowing Governance (ARCH-014): The Telegram listener and interactive assistant daemons must enforce Poka-Yoke anti-narrowing controls. Unconstrained ILIKE full-text matching against jobsite notes fields is strictly prohibited to prevent general business queries from binding to dense historical records (e.g. Bid #39). All inquiries must filter against the 120+ enterprise stop-word catalog, detect broad semantic phrases ("our cost", "system to be used", "receive payments", "website capabilities"), fall back to GENERAL_OPERATIONAL_CONTEXT, and enforce Rule 7 prompt governance across all 4 core service lines.
  7. 24/7 Enterprise AI Employee Governance, Pre-Change Rollback Ledger & FinOps Circuit Breaker (BUG-163): All autonomous and executive-directed mutations executed via @Georgebytesbot or /api/v1/ai-employee/* must first snapshot every affected database row's before_state into "AIEmployeeChangeLedger" and stage a Change-Set (#CS-<id>) with 1-tap Telegram inline buttons ([✅ Apply #CS-<id>] / [↩️ Rollback #CS-<id>]). Outbound Telegram messages enforce link_preview_options: {"is_disabled": True} to prevent third-party preview cards from obscuring reports. Every AI response is verified by the Deterministic Citation Firewall against live PostgreSQL IDs, and daily/monthly API spend is enforced by "AIEmployeeBudgetLedger" ($0.50/day and $15.00/month hard ceiling with zero-cost SQL fallback).
  8. Proportional First-Pass Engineering & Host PC Approval Gate (GOV-04 Revised / SigmaKnowledgeScars #268 — 11/12/2026): Mandatory chat-hook injection (fortune500-closed-loop-governor / scripts/agy_fortune500_gate_hook.py) is set to "enabled": false in .agents/hooks.json to prevent per-turn prompt bloat and speculative 4-layer wrapper inflation. All agent engineering enforces Smallest Proven Fix First (never invent new tables, daemons, cron loops, or multi-layer wrappers when a config edit, SQL index, or deleting dead code solves the measured bottleneck), freezes new meta-infrastructure unless required by an active customer or revenue campaign, and pauses for explicit CEO Humberto Dominguez approval before modifying any host PC file (/mnt/c/..., .wslconfig, Docker Desktop, crontab, systemd, or .bashrc).

5.0 Verification (Zero-Defect Check)

  • Run docker top hwb_agent_worker to verify all 4 supervisor processes are actively executing.
  • Inspect HWB-IT-SYSTEM-LOGS/tessa_regression_audit.log to confirm the latest regression audit passed with Grade A+ certification.
  • Run python3 scripts/peter_sentinel.py verify to confirm backups/latest/hwb_dev_db.dump is under 90 minutes old, locked to chmod 600, and passes SHA-256 verification (with sigma-peter.service permanently disabled).
  • Execute the 4-tier regression battery and verify 100% pass rates across all modules.
