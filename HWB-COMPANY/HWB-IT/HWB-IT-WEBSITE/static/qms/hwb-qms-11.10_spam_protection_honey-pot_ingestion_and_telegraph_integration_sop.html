Standard Operating Procedure: Mobile Operations System & Telegram Executive Command

1.0 Purpose

This Standard Operating Procedure (SOP) defines the operational guidelines for HWB Cleaning Services' Mobile Operations System (MOS v3.0). It establishes how the CEO controls the entire business directly from his phone using Telegram, manages automated commercial construction bidding, prevents marketing form spam, and uses decoupled background tasks to perform heavy web automation.

2.0 Scope

This procedure applies to:

  • The Telegram executive listener bot (scripts/telegram_listener.py) running inside the container worker.
  • The host-level decoupled automation worker (scripts/host_task_runner.py) running on Linux host infrastructure.
  • The public quote form honeypot filter on the web application route (/get-quote).
  • The PostgreSQL database queues (task_queue, PendingOutbox, and ConstructionBids).
  • The Telegram WebApp (TMA) Scope Configurator (/tma/estimator).

3.0 Procedure

3.1 Website Form Protection & Honeypot Blackhole

To block fake internet bots and spam submissions from polluting company databases and clogging email servers:

  • Form submissions entering the /get-quote route are inspected before any database insert or email staging occurs.
  • The system checks the submitted company name, contact name, and message for spam indicators:
    • Suspicious Web Links: Inclusion of prefixes such as http://, https://, graph.org, or top-level domains like .org/, .net/, and .com/.
    • Financial Spam Phrases: Phrases such as us dollars, usdc, crypto transfer, balance payment, or get the transfer.
  • The Silent Blackhole Rule: If spam signatures are identified, the system drops the data silently. It skips database writes and does not notify the outbox. The bot is shown a standard confirmation screen (quote_success.html) so it stops resubmitting.

3.2 The Telegram Mobile Operations System (MOS v3.0) - The 6 Strategic Frontiers

The Telegram bot is an industrial executive remote control for company operations, operating across six key frontiers:

  1. 1-Tap Takeoff Calculation & Proposal Approval:

    When an Invitation to Bid (ITB) email arrives from general contractors, the system extracts the project details, calculates the estimated square footage, creates a proposal draft, and sends an interactive card to Telegram. The CEO can review the price and tap a single inline button (Approve & Submit or Adjust Scope) to advance the deal.

  2. Telegram Mini-App (TMA) Scope Configurator:

    By tapping Adjust Scope, an interactive web slider opens inside Telegram (/tma/estimator). The CEO can dynamically toggle scopes (Rough Clean, Final Clean, Touch-Up Clean, Floor Scrubbing, Pressure Washing) and see immediate price adjustments before confirming.

  3. Gemini 2.5 Flash Voice Directives:

    The CEO can hold the Telegram microphone button and speak natural instructions (e.g., "George, check our outbox, what bids are pending?"). The bot downloads the audio file, streams it to the Gemini speech-to-text and reasoning engine, and responds with immediate status and actions taken.

  4. Blueprint Vision & Drawing Sheet Analysis:

    The CEO can take a photo of an architectural floor plan or forward a blueprint image into Telegram. The vision engine identifies finish tags (such as VCT, sealed concrete, or ceramic tile), estimates the square footage, and returns an instant post-construction cleaning price breakdown.

  5. Decoupled Subcontractor Portal Automation (Host Task Runner):

    Portal bidding tasks (such as downloading plans from BuildingConnected or uploading completed bid forms) require browser automation tools like Playwright. To keep Docker containers lightweight, the container deposits a job record into the PostgreSQL task_queue table. A native host runner (scripts/host_task_runner.py) picks up the job, operates the browser, and reports completion back to Telegram.

  6. Daily Executive Briefing Daemon:

    Every morning at 7:00 AM Central Time, an automated daemon audits pending bids, review approvals, active outbox emails, and server health. It compiles a concise morning brief and delivers it to the CEO's Telegram inbox.

3.3 Telegraph Instant Article Publishing

When large technical audits, walkthroughs, or system performance logs exceed Telegram's message character limits:

  • The system publishes the structured report to the Telegra.ph publishing platform using an automated API token.
  • A summary card with an instant-view reading link is delivered to Telegram, providing a distraction-free mobile reading experience.

4.0 Verification (Zero-Defect Check)

  • Telegram Responsiveness: Send /status to the bot in Telegram. Confirm that it replies with active container health, active bid counts, and database connection status within 3 seconds.
  • Host Runner Heartbeat: Verify that scripts/host_task_runner.py is actively polling the task_queue table and claims pending jobs without errors.
  • Honeypot Integrity: Submit a test lead containing an external hyperlink in the company name. Confirm that the application returns HTTP 200 but creates zero records in the Leads table.
  • Discrepancy Tagging: When estimating bids with heuristic calibrations, confirm that the Telegram notification card explicitly displays the amber alert warning.
