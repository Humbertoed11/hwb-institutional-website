Standard Operating Procedure: Disaster Recovery & Shadow Snapshots

1.0 Purpose

This document explains how to keep our website running and protect our business data if files are broken, deleted by mistake, or if a system crash happens. It provides a simple step-by-step path to backup our code and restore it instantly using safety snapshots.

2.0 Scope

This protocol applies to all active website pages, application settings, database structures, and artificial intelligence configurations inside our development workspaces.

3.0 Operational Roles

  • George (Systems Architect): In charge of starting emergency rollbacks and confirming that the system is fully healthy.
  • Peter (Recovery Specialist): In charge of creating regular backups and restoring the files.
  • CEO (Humberto Dominguez): Final approval authority for any full system rollbacks.

4.0 Safety Snapshot Setup

To prevent loss of work, our system is protected by a background script called Peter Sentinel. This script takes a quick picture of our work (a "Shadow Snapshot") and saves it locally. This runs in the background, but we can also start it by hand.

Important Safety Standard

Every time we begin a complex project, we must run the backup script by hand to create an instant rollback point. This ensures we can easily undo our changes if the new implementation breaks the site.

5.0 Step-by-Step Procedures

5.1 Creating a Rollback Point (By Hand)

Before modifying any code, a team member must create a physical rollback point using these simple steps:

  1. Open the terminal in the main project folder.
  2. Run our safety backup script using the local virtual environment: 
    .venv_agent/bin/python scripts/peter_sentinel.py
  3. Verify that the script outputs a success message listing the protected items. This script automatically saves copies of our main application controller (main_app.py), orchestrator settings, database models, agent logs, and configuration settings (.env).
  4. The snapshot will be saved in the safety vault directory: 
    HWB-COMPANY/HWB-IT/HWB-IT-SYSTEM-LOGS/shadow_snapshots/[TIMESTAMP]/

5.2 The Panic Button: Restoring Broken Files

If the website stops working or if files become broken during development, execute the restoration sequence:

  1. Navigate to the safety vault directory to locate your target backup timestamp folder: 
    HWB-COMPANY/HWB-IT/HWB-IT-SYSTEM-LOGS/shadow_snapshots/
  2. Copy all backed-up files from the chosen timestamp folder directly back into your active website directory: 
    cp -r HWB-COMPANY/HWB-IT/HWB-IT-SYSTEM-LOGS/shadow_snapshots/[TIMESTAMP]/* HWB-COMPANY/HWB-IT/HWB-IT-WEBSITE/
  3. If database files are corrupted or missing, restore them using the latest `.sql` database copy inside our database backup folder.

6.0 Verification (Zero-Defect Check)

After a restore operation, the team must verify that the website is fully healthy:

  • Run a diagnostic script to check for logical errors or missing dependencies: 
    .venv_agent/bin/python diag_dashboard.py
  • Verify that the local website servers start without error and are accessible on ports 5000 and 8000.
  • Open the web manual in a web browser and verify that all dynamic links and standard procedures load correctly.
