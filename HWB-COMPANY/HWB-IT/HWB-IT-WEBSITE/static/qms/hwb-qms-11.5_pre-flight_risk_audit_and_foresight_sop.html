Standard Operating Procedure: Pre-Flight Risk Audit & Foresight

1.0 Purpose

To define the "Foresight" protocol for the Antigravity CLI. This SOP ensures that agents do not repeat historical catastrophic failures (e.g., the 04/26/2026 Magnitude 10 Collapse) by mandating a mandatory risk audit prior to executing high-impact structural changes.

2.0 The "Over-Hardening" Paradox

A review of HWB-QMS-FORM-005-MISTAKE-LOG reveals that our most severe systemic failures occurred when agents attempted "Multi-Phase Roadmaps" in a single session without testing intermediate steps. Over-hardening (e.g., excessively strict Content Security Policies or aggressive Git cleans) leads to silent data loss and deployment paralysis.

3.0 The Pre-Flight Mandates

Before executing any structural codebase modification (e.g., routing changes, database migrations, or server config updates), the agent MUST adhere to the following:

  1. The Atomic Protocol: No more "Multi-Phase" deployments in a single turn. Changes must be executed and validated one logical unit at a time.
  2. The Marker Rule (Code Injection): NEVER use regex for multi-line HTML code blocks. Agents must use precise start/end markers (or the replace tool) to prevent character escaping and content erosion (Mistake #9).
  3. The Cloud-Mirror Sync: Before any deployment or Git commit, the agent MUST run git ls-files to verify that critical database files (e.g., SQLite DBs) are not accidentally ignored (Mistake #14).
  4. The Route Gatekeeper: Before stating a URL or linking an asset, the agent MUST grep the main_app.py routes to ensure 100% parity (Mistake #3).
Danger (Catastrophic Rollback Risk)

Never run git clean -fd without CEO approval. This action previously resulted in the deletion of uncommitted Knowledge Base (PKB) assets. If a rollback is required, use git checkout and preserve untracked files.

4.0 The Foresight Workflow

  1. Assess Directive: Agent receives task.
  2. Query History: Agent queries SigmaWalkthroughs or the Mistake Log for related failures.
  3. State the Risk: Agent acknowledges the historical risk in the terminal using the Topic Model.
  4. Execute Atomically: Agent applies the fix one step at a time.

5.0 Verification (Zero-Defect Check)

  • No multi-line regex replacements executed on HTML files.
  • No files deleted via aggressive Git cleaning.
  • All URL routes verified against the backend configuration.
