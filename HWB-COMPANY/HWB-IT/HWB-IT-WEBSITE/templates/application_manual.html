1.0 Chapter 1: Getting Started, Login & Security Alerts

1.1 Feature Overview & System Purpose

The Login and Authentication subsystem provides encrypted entry into the HWB Operations Platform. Every team member signs in with their assigned username and password. The system enforces strict SOC 2 Type II security measures, including automatic inactivity logouts and single-session locks to protect commercial client records and proprietary cleaning contracts.

Security Standard: To prevent unauthorized access on shared office computers or jobsite tablets, the platform automatically logs out any session after 30 minutes of no mouse or keyboard activity.

1.2 User Access & Role Requirements

All active employees with an assigned account can access the login gateway. Role assignment occurs upon user creation by an Administrator.

1.4 Step-by-Step Procedure: Logging In Safely

  1. Open your web browser and navigate to https://hwbcleaning.com/login.
  2. Enter your assigned username into the Username or Email field.
  3. Enter your password into the Password field.
  4. Click Sign In.
✓ Expected Result: The platform validates your credentials, opens the Operations Control Hub, and displays your active role badge in the upper right navigation rack.

1.5 Troubleshooting & Common Inquiries

  • Forgotten Password: Contact an Administrator or Executive to trigger a temporary password reset. You will be prompted to set a new password on your next login.
  • Session Inactivity Warning: If the screen dims and displays the security dialog, click Stay to resume working without losing unsaved changes.

2.0 Chapter 2: Commercial Leads & CRM Pipeline

2.1 Feature Overview & System Purpose

The Commercial Leads Workspace is the central engine for outside sales and telemarketing operations. It provides verified commercial property data across the state of Texas, specifically optimized for licensed childcare centers, private schools, and commercial facilities. Sales callers use this view to review building size, verify key decision makers, place phone calls, and log real-time progress notes.

Texas Statewide Mandate: In accordance with Executive Mandate 2026-07-22, lead queries and GIS synchronizers load commercial facilities statewide across all Texas metropolitan areas without geographic restrictions.

2.2 User Access & Permissions

Requires Sales, Manager, Executive, or Admin role with perm_leads_view = true. Editing call records requires perm_leads_edit = true.

2.4 Step-by-Step Procedure: Conducting a Daily Calling Sprint

  1. From the top navigation bar, select Commercial Leads.
  2. Click Columns and select the 📞 Calling Sprint quick preset.
  3. Use the search bar or city dropdown to focus on your designated territory (e.g., Dallas, Plano, Fort Worth).
  4. Click the phone number or row for the target facility to review recent notes.
  5. After completing the phone call, update the status dropdown (e.g., Contacted, Walkthrough Scheduled).
  6. Type your call summary into the Call Notes box and click Save Changes.
✓ Expected Result: The record updates in real time, the green confirmation toast appears, and the call is logged into the audit history.

3.4 Step-by-Step Procedure: Generating a Client Cleaning Proposal

  1. Open the Bidding & Estimating workspace from the top navigation.
  2. Enter the customer's total cleanable square footage into the Square Footage field.
  3. Select the property type (e.g., Childcare / School).

4.0 Chapter 4: Marketing Outbox & Calendar Walkthroughs

4.1 Feature Overview & System Purpose

The Marketing Outbox manages automated email sequences, marketing flyers, and customer correspondence. Under the institutional Outbox Protocol (HWB-COM-001), automated marketing emails are held in a review staging queue. This allows executive management to review copy, inspect recipient addresses, and verify alignment before emails are sent via the Microsoft Graph API.

Single Outbound Gateway: All transactional and marketing emails route exclusively through the official Microsoft 365 Exchange tenant. Third-party marketing tools or personal inboxes are prohibited.

4.2 User Access & Permissions

Reviewing and releasing queued emails requires Manager, Executive, or Admin privileges (perm_outbox_view = true and perm_outbox_edit = true).

6.0 Chapter 6: User Accounts, Roles & Administration

6.1 Feature Overview & System Purpose

The User Accounts and Security module manages employee login credentials, role assignments, and granular permissions across 11 distinct platform areas. To eliminate setup errors and ensure consistent compliance, the system introduces a one-click Reset to Role Defaults button that instantly restores standard corporate access permissions for any chosen role.

Poka-Yoke Error Safeguard (BUG-120): When an administrator selects a role from the dropdown, all 11 module checkboxes auto-fill to corporate standards. If an administrator accidentally checks or unchecks permission boxes, clicking Reset to Role Defaults immediately restores the correct preset.

6.3 Step-by-Step Procedure: Creating a User & Restoring Role Defaults

  1. Sign in with an Admin or Executive account and open User Accounts.
  2. To modify an existing user, click the blue Edit button next to their name in the user roster.
  3. In the System Role dropdown, pick the employee's designated role (e.g., Sales).
  4. Notice that the 11 module checkboxes immediately adjust to match that role's standard permissions.
  5. If you test or alter any checkbox and want to return to standard corporate configuration, click Reset to Role Defaults.
  6. Click Save User Account to commit the changes to the PostgreSQL database.
✓ Expected Result: The account updates immediately, the changes are written to the database, and the user's next page request enforces their updated permissions.

6.4 Security Governance & Poka-Yoke Protections

  • Tamper-Proof Role Presets: Custom changes are allowed for edge cases, but clicking Reset to Role Defaults instantly reverts checkboxes to verified corporate policy.
  • Audit Logging: Every user role change and password reset event is written to immutable database logs with the administrator's timestamp and IP address.
