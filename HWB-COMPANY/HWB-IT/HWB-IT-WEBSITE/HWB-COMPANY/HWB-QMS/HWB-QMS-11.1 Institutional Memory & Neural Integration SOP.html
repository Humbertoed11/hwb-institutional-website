Standard Operating Procedure: Institutional Memory & Neural Integration

1.0 Purpose

To define the definitive "Neural Map" of the SigmaFidelity™ ecosystem for the Antigravity CLI. This SOP ensures 100% data continuity by instructing agents on how to digest, initialize, and maintain our multi-tier memory systems.

2.0 The 4-Tier Memory Architecture

The agent MUST prioritize data retrieval according to this hierarchy:

Tier 1: The Relational Core (PostgreSQL)

  • Engine: Docker Container hwb_postgres_dev.
  • Database: hwb_dev_db.
  • Key Synapses (Monolithic):
    • SigmaInteractionCore: Consolidated CEO/Agent audit logs and technical telemetry.
    • SigmaKnowledgeScars: Integrated bug registry and historical failure rules.
    • SigmaSystemCore: Authoritative system state (paritied with Markdown).
    • Leads: 37-column CRM engine.

Tier 2: The Modular Store (SQLite)

  • Engine: Local files in HWB-COMPANY/HWB-DATA/*.db.

Tier 3: Institutional Mandates (HTML/Git)

  • Files: GEMINI.md and HWB-SESSION-RECOVERY.md.
  • Mandate: These serve as "Cold Boot" instructions. Effective 05-22-2026, all other SOPs are authored in HTML directly.

Tier 4: Episodic Memory (Antigravity Brain)

  • Location: ~/.gemini/antigravity-cli/brain/.
Technical Logic

The transition from Markdown to HTML ensures zero-latency ingestion into the Compliance Engine and eliminates the need for manual migration scripts.

3.0 Architectural Achievements (May 2026 Baseline)

  1. "Everyday Words" Standard: Clinical, simple English only.
  2. Industrial Modernization: Vanilla CSS, Identity Cards, and compressed UI.
  3. Autonomous Startup: Mandatory connectivity checks.
  4. HTML Source Mandate: All new knowledge authored in .html format.

4.0 Initialization Procedure (The "Neural Wake-up")

  1. Read GEMINI.md: Load mandates.
  2. Read HWB-SESSION-RECOVERY.md: Sync objective.
  3. Execute Audit: Run startup_master.sh.
  4. Confirm Alignment: Confirm synchronization in 3rd person.
