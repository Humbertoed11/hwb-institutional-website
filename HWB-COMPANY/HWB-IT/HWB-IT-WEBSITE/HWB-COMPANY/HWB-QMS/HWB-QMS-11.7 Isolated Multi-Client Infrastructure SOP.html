Standard Operating Procedure: Isolated Multi-Client Infrastructure

1.0 Purpose

To define the mandatory architecture for scaling the SigmaFidelity™ ecosystem to support non-cleaning clients. This SOP ensures Total Isolation between client environments, preventing data leaks and configuration conflicts while maintaining monolithic intelligence standards.

2.0 Directory Architecture

All new non-cleaning client projects must be placed in a dedicated root directory outside of the primary gemini_projects workspace.

  • Root Path: /home/humbertoed/autonomous-nexus/
  • Project Path: /home/humbertoed/autonomous-nexus/[client-name]/

3.0 Docker Isolation Standards

Each client project must utilize a standalone docker-compose.yml file with the following constraints:

  1. Private Network: A dedicated bridge network (e.g., [client]-net) to isolate internal traffic.
  2. Isolated Databases: A dedicated PostgreSQL or SQLite instance unique to the client. No cross-database sharing is permitted.
  3. Unique Container Names: Containers must be prefixed with the client ID (e.g., clientx_web_app).
  4. Isolated Volumes: Permanent storage must be mapped to local paths within the client directory.

4.0 Neural Brain Isolation

Each client environment must maintain its own Neural Interaction Core to ensure institutional memory is client-specific.

  • Local Mandates: A unique GEMINI.md in the project root defining client-specific business history and rules.
  • Local SQL Brain: A client-specific SigmaInteractionCore table for audit traceability.
Security Logic

Total separation means that a failure or vulnerability in one client environment cannot compromise the integrity of the cleaning services factory or other client projects.

5.0 Initialization Procedure

  1. Scaffold Root: mkdir -p /home/humbertoed/autonomous-nexus/[client].
  2. Bootstrap Docker: Create docker-compose.yml using the SigmaFidelity standard.
  3. Inject Mandates: Copy the global GEMINI.md and refine the local version for the new client.
  4. Deploy: docker-compose up -d.

6.0 Verification (Zero-Defect Check)

  • Are the new client files located outside of gemini_projects?
  • Does the docker ps output show isolated container prefixes?
  • Is the client data stored in a unique database instance?
