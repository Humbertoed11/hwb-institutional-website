1.0 Purpose & Scope

Establishes the mandatory Two-Part Enterprise Web & Backoffice Performance Standard for https://www.hwbcleaning.com/ and /admin/operations across Azure App Service (hwb-institutional-website), Gunicorn workers, PostgreSQL connection pools, covering SQL indexes, asynchronous telemetry caches, and Server-Side Jinja DOM Pruning.

2.0 Part I: 5-Pillar Public Surface & Stateless Worker Standard (v1.0.0)

  • Pillar 1 (Azure Infrastructure Hardening): AlwaysOn=true, Use32BitWorkerProcess=false, and HealthCheckPath="/heartbeat".
  • Pillar 2 (Stateless Workers & Single-Execution Boot Guard): Preloaded Gunicorn topology (--preload --workers 2 --threads 8) and atomic OS lock /tmp/hwb_enterprise_boot.lock in main_app.py.
  • Pillar 3 (Zero-Round-Trip Pooled DB Connections): options="-c timezone=America/Chicago" + TCP keepalives at connection creation in core/services/database.py with DB_POOL_MAX=10.
  • Pillar 4 (In-Memory Version Cache): @functools.lru_cache(maxsize=1) on get_version_info() in core/services/version_service.py.
  • Pillar 5 (Next-Gen WebP & Split Edge Caching): 67 WebP assets (-92.7% homepage image weight) and split Cache-Control headers (s-maxage=3600 + clean Vary: Accept-Encoding for anonymous public routes; strict private, no-store for authenticated routes).

3.0 Part II: 5-Pillar Enterprise Backoffice & Post-Login Workspace Architecture (v1.1.0)

  • Pillar 1 (Async Background Telemetry Cache): 300-second TTL thread-safe in-memory cache (_TELEMETRY_CACHE) with non-blocking background refresh in core/services/self_healing_engine.py and core/services/credential_sentinel.py; it_telemetry is computed only when active_view in ('it_department', 'it_telemetry').
  • Pillar 2 (Set-Based SQL Aggregation & Covering Indexes): Composite indexes idx_global_activities_parent_lookup and idx_campaign_recipients_lead_lookup in database/schema_engine.py; correlated subqueries replaced with single-pass LEFT JOIN aggregations in blueprints/operations.py.
  • Pillar 3 (Strict Active-View CQRS SQL Isolation & 30s Cached Sidebar Counts): _get_operations_sidebar_counts (30s TTL) and active-view SQL gating in blueprints/operations.py so switching tabs queries only the active department.
  • Pillar 4 (Server-Side Jinja DOM Pruning & Externalized JS): Inactive <div id="view-..."> trees and department modals in templates/backoffice_operations.html are pruned via {% if active_view == '...' %} and static JS is served via /static/js/backoffice_operations_core.js, reducing HTML payload from 2.6–3.3 MB to <150 KB.
  • Pillar 5 (Sub-150ms Tab Switching & Regression Gate): Verified via scripts/test_web_performance_rack_14.py across all 6 core departments (leads, accounts, construction_bids, marketing, workforce, it_department).
